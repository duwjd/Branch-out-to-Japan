# 결정 — 실 메일 발송을 보류하고 링크 노출을 정식 경로로 승격한다 (2026-09-02)

> Phase 1 M15-3a(#66) 범위 번복. 하루 전까지의 계획은 **`MAIL_MODE` 3경로 어댑터**(devlink|gmail|resend)였다.

## 배경 — 하루 만에 전제가 두 번 바뀌었다

8/31 에 실 발송 계획이 한 번 흔들렸다. Resend API 키는 받았으나 `onboarding@resend.dev` 는 **본인 계정 메일로만** 가고, 회사 도메인 `10k1m.com` 은 **사용 불가**로 확정됐다. 그래서 Gmail SMTP 를 끼워 **도메인 결정과 개발을 분리**하는 3경로 어댑터로 범위를 조정했다([[../sprints/2026-09-sp1]] 1일차 기록).

9/2 에 그 조정 자체가 철회됐다. **이번 스프린트에서 실 발송을 하지 않는다**는 결정이다. 이메일 가입은 지금처럼 인증 링크를 화면에 보여주는 방식으로 간다.

## 무엇이 문제였나 — 임시 플래그가 지뢰였다

`lib/server/mailer.ts` 는 이런 모양이었다.

```ts
const exposeLink = process.env.NODE_ENV !== 'production' || process.env.AUTH_MAIL_MODE === 'devlink';
```

운영에서 `AUTH_MAIL_MODE=devlink` 를 **넣지 않으면** 링크가 억제되는데, 실 발송이 없으므로 **아무도 인증을 완료할 수 없다 — 가입 전원 차단**이다. 코드가 그 사실을 알고 `logger.error` 로 소리치는 상태로 살고 있었다.

이 분기는 "곧 실 발송이 붙는다"는 전제 위에 서 있었다. 전제가 사라지면 남는 것은 **켜는 걸 잊으면 서비스가 죽는 스위치**뿐이다.

## 결정

1. **`AUTH_MAIL_MODE` 플래그를 제거한다.** `NODE_ENV` 분기도 함께. `sendAuthMail` 은 **항상** 링크를 돌려준다.
2. **반환 계약 `{ devLink }` 는 그대로 둔다.** 호출부 3곳(`signup`·`resend`·`forgot`)과 화면 3곳(`EmailAuthPanel`·`ResendVerifyButton`·`PasswordChange`)을 건드리지 않는다. 실 발송을 붙일 때 `devLink` 가 다시 null 이 될 수 있는 자리를 남겨 둔다.
3. **경고를 없애지 않고 방향을 뒤집는다.** `error`("링크가 안 나간다") → `warn`("실 발송 없이 운영 중 · 이메일 소유 검증이 성립하지 않는다"). 운영에서 프로세스당 한 번.
4. **교체 지점은 계속 이 함수 하나다.** 3경로 어댑터를 만들지 않는 이유는 **경로가 하나뿐일 때 디스패치는 비용만 남기기** 때문이다. 실 발송을 붙이는 시점에 그 자리에서 만든다.

## 감수하는 것

| | |
|---|---|
| **이메일 소유 검증이 성립하지 않는다** | 링크가 요청한 쪽으로 곧장 돌아가므로, 남의 주소로 가입해도 응답에 실린 링크를 눌러 `emailVerified` 를 통과할 수 있다. **아는 사람만 부르는 폐쇄 UT 에서만 유효하다** |
| **테스터를 메일로 받을 수 없다** | 2026-08-31 리스크 R1 이 열어 두려던 길이 닫힌다. 테스터에게는 링크를 다른 수단으로 전달하거나 대면·화면 공유로 진행해야 한다 |
| **U1~U6 이 무의미해진다** | 도메인 구입·Gmail 앱 비밀번호·`.env`·Vercel 환경변수·DNS 가 전부 실 발송 전제였다. [#68](https://github.com/duwjd/Branch-out-to-Japan/issues/68) 에서 보류로 내리고 U7(테스터 모집)만 남긴다 |
| **#67(실발송 E2E)이 검증할 대상을 잃는다** | 닫지 않고 다음 스프린트 백로그로 넘긴다 |

**새로 생기는 위험이 아니라는 점이 중요하다.** 운영은 이미 `AUTH_MAIL_MODE=devlink` 로 돌고 있었고, 소유 검증 부재는 그때부터 사실이었다. 이번에 바뀐 것은 **그 사실이 문서와 코드에 적혔다**는 것뿐이다.

## 되돌리는 조건

**공개 모집으로 넘어갈 때.** 아는 사람이 아닌 사용자를 받는 순간 소유 검증 부재는 감수할 수 있는 것이 아니게 된다. 그때 `sendAuthMail` 내부에 발송을 붙이고 `devLink` 를 운영에서 null 로 되돌린다. 발신 도메인 결정(U1)이 그 작업의 선행이다.
