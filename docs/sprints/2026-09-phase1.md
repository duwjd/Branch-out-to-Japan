## 목표

Phase 0 을 종료하며 비워 뒀던 [[../04-roadmap]] §Phase 1 을 이 스프린트로 채운다.

| # | 목표 | 완료 판정 |
|---|---|---|
| **1** | **상세페이지 안정화** — 시간 초과로 생성이 안 되는 경우를 없앤다 | 실패가 나면 어느 단계가 얼마를 먹었는지 자산 레코드로 말할 수 있다 · 예산 초과가 `failed` 가 아니라 **강등**으로 끝난다 |
| **2** | **상세페이지 입력 피로 해소** — 입력할 게 너무 많다 | 같은 제품으로 **두 번째** 상세를 만들 때 필수 입력이 **제품 선택 하나**로 끝난다 |
| **3** | **로그인 개선** — 소셜 목업을 숨기고 실제 이메일 인증을 되게 한다 | 인증 없이 세션을 받을 수 있는 경로가 없다 · 실제 메일함으로 인증 링크가 도착하고 클릭하면 가입이 완료된다 |

**범위 밖.** UT 백로그의 M12-C(말과 화면 맞추기)·M12-D(지불 판단 정보)는 이번에 하지 않는다. 회고에서 Phase 2 후보로 넘긴다.

> 목표 2 를 **제품 선택 프리필**로 푸는 이유는 그것이 입력을 줄이면서 UT P0 세 건(UT-58 폐루프 · UT-33 제품 타입 오판 · UT-25 한국어 브랜드명 **11/12 재현**)을 같은 코드 자리에서 함께 닫기 때문이다.

## 리스크 · 차단

| # | 무엇 | 영향 | 대응 |
|---|---|---|---|
| **R1** | **Resend 발신 도메인 DNS(SPF/DKIM) 는 사용자만 할 수 있다.** API 키도 `.env*` 편집 차단으로 사용자 수동 반영 | 목표 3 의 마지막 단계가 통째로 대기 | `MAIL_MODE`(`devlink`\|`resend`) 2경로로 만들어 **키 없이도 코드가 완성·머지**되게 한다. 1일차에 요청 |
| **R2** | `gh` CLI 미로그인 — 대화형이라 대신 못 한다 | 이슈 생성 불가 | 사용자가 `! gh auth login`. 그 전까지 이 문서 작업 보드만 운영 |
| **R3** | **M13 은 재현 데이터가 없다** — UT 는 20/20 성공했고 실패는 그 이후 조건 | 원인 추정으로 잘못 고칠 위험 | 계기(13-1)를 먼저 붙이고 데이터가 모인 뒤 13-3 을 한다 |
| **R4** | 함수 상한 **300초는 못 올린다**(Vercel Hobby) | 근본 해결 불가 | 그 안에서 사는 방법(강등·타임아웃)만 한다. 잡 분할·큐는 이번 범위 밖 |
| **R5** | 목표 3 종료 시 **소셜 로그인이 사라진다** | 기존 목 세션 사용자 로그인 경로 상실 | `AuthProvider` 타입은 남겨 기존 쿠키·배지가 죽지 않게 한다 |
