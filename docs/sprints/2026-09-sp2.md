## 목표

SP1 은 상세페이지를 **믿고 쓸 수 있게** 만들었다. SP2 는 **쓰기 쉽게** 만든다.

| # | 목표 | 완료 판정 |
|---|---|---|
| **1** | **상세 폼을 결과 중심으로 재구성** — 입력이 아니라 **결과물**이 화면의 주어가 된다 | 필수 입력만으로 생성이 시작된다 · **폼에서** 지금 몇 블록이 붙는지와 무엇을 채우면 뭐가 늘어나는지 보인다 · 빠진 블록 목록을 "숙제"로 읽는 구간이 없다 |
| **2** | **입력을 사용자 대신 채운다** — KR 상세 원본에서 스펙을 뽑는다 | KR 원본을 올리면 스펙 7칸(용량·제조사·원산지·전성분·성분표·사용법·주의사항)이 **출처 표시와 함께** 차고, 전부 고칠 수 있다 |
| **3** | **제품 등록 피로 해소** — 이미지만으로 후보를 찾는다 | 제품컷만 올리면 후보가 뜨고, 고르면 제품 정보가 찬다 · 후보가 없으면 수동 입력이 **즉시** 열린다 |

**품질 가드 (세 목표 공통).** 입력을 줄이는 변경이 산출물을 얇게 만들면 실패다.
판정: **같은 제품·같은 자료로 재생성했을 때 붙는 블록 수가 줄지 않는다.** 회귀 케이스를 `blockPack.test.ts` 에 고정한다.

**범위 밖.** 이메일 실 발송(#67 · 사용자 작업 U1~U6) — SP1 결정 유지([[../decisions/2026-09-02-실메일-보류-devlink-정식화]]). UT 백로그의 M12-C 중 UT-27(매칭 화면 고지)·M12-D(지불 판단 정보)도 이번엔 하지 않는다.

> **목표 1 은 새 아이디어가 아니라 UT 가 이미 요구한 것이다.** `/app/studio/detail` 확인 화면은 UT **관찰 지점 2위(7/20)** 였고, 사용자는 빠진 블록 10~13개 목록을 **"내가 채워야 할 숙제"** 로 읽었다 — *"이거 다 채우려면 시간이 더 드는데 싶어 잠깐 멈칫했다"*(P15) · *"저희 브랜드는 정보가 너무 없어서 이 서비스가 만들어줄 게 별로 없구나 싶어졌어요"*(P20).
>
> 진단은 하나다. **시스템은 이미 "무엇을 채우면 어느 블록이 붙는지" 아는데, 그걸 다 채운 뒤에야 보여준다.** `checkRequirement()` 가 블록별로 `{reason, fixHint}` 를 돌려주는데 확인 단계에서만 렌더된다. 이 신호를 **앞으로 당기고 블록을 1급 단위로 올리는 것**이 이번 스프린트의 뼈대다.

**함께 닫히는 UT 백로그** — 목표 1 과 **같은 코드 자리**다: **UT-26**(P0 · 시그니처 블록 전멸 시 추천 배지) · **UT-31**(P2 · placeholder 를 입력값으로 오인).

## 자동 입력 설계 — 왜 KR 원본이 먼저인가

원안은 "제품 이미지 → 웹 검색 → 후보 → 선택 → 자동 입력"이었다. **유효하지만 그대로 두면 절약폭이 작다.**

`products` 테이블 필드는 **4개뿐**이다(`nameKr` 필수 · `nameJa` · `category` · `memo`). 제품 등록은 이미 작은 폼이라 웹 검색을 붙여도 아끼는 건 3칸이다.

**진짜 피로는 상세 폼의 37칸**이고, 그중 스펙 7칸은 **사용자가 이미 업로드하는 KR 상세 원본에 텍스트로 박혀 있다.** 브랜드가 소유한 1차 자료라 웹보다 정확하고, 환각 위험이 낮고, 저렴하다(비전 1콜 · 검색 왕복 없음).

그래서 담당을 나눈다 — **웹 검색이 폴백으로 밀린 게 아니라 잘하는 자리가 다르다.**

| 순위 | 소스 | 무엇을 채우나 | 왜 |
|---|---|---|---|
| **①** | **KR 상세 원본 판독** (M17) | 스펙 7칸 | 이미 올리는 자료 · 브랜드 소유 1차 자료 |
| **②** | **웹 검색** (M18) | `nameJa`(일본 등재명) · `category` | 원본에 **없는** 값. 브랜드가 모르는 경우가 많다 |
| **③** | **수동** | 나머지 전부 | 둘 다 실패하면 지금 경로 그대로 |

**규정 가드.** 이 서비스에는 약기법 게이트가 있다(`assembleBlockSlots`). 자동으로 채운 값이 검증 없이 발행되면 그게 곧 규정 사고다. 셋을 건다.

1. 자동 채움 값은 **항상 출처 배지**와 함께 보인다 (SP1 프리필 `data-prefilled` 관례 재사용)
2. **전성분 · 효능 문구 · 시험 결과는 사용자 확인 전까지 해당 블록을 붙이지 않는다**
3. 웹 검색 결과는 **출처 URL 을 함께 저장**한다
