# 문서 규약 (지식베이스)

> 이 저장소의 문서를 **컨플루언스·노션처럼 다루기 위한 규칙**이다. 홈은 [README.md](README.md).
> 규칙을 어긴 문서는 `npm run docs:check` 가 잡는다.

## 1. 왜 규약이 필요한가

문서가 100편이 넘는다. **문서를 열기 전에는 그것이 지금 기준인지, 지난 기록인지, 이미 틀린 것인지 알 수 없었다.**
실제로 `design/DESIGN.md` 는 "색은 전환 이전 as-built 기록"이라는 경고를 본문 인용구로 달아 이 문제를 막고 있었다. 그 판단을 **문서 속성으로 올려** 목록에서 바로 읽히게 한다.

## 2. 문서 속성 (프론트매터)

모든 `.md` 파일 맨 위에 둔다.

```yaml
---
title: 04 · 로드맵
space: 전략·제품
status: 정본
phase: Phase 0
owner: 정원
updated: 2026-08-31
tags: [로드맵, 진척]
---
```

| 키 | 필수 | 값 |
|---|---|---|
| `title` | ✅ | 문서 제목. 본문 첫 `# ` 과 같게 유지한다 |
| `space` | ✅ | 아래 §3 의 9개 중 하나 |
| `status` | ✅ | `정본` · `초안` · `이력` · `폐기` (§4) |
| `phase` | ✅ | 그 문서가 만들어진 Phase. 지금은 전부 `Phase 0` |
| `updated` | ✅ | 마지막으로 **내용이 바뀐** 날 (`YYYY-MM-DD`). 오타 수정은 갱신이 아니다 |
| `owner` | | 이 문서에 대해 답할 사람. 비워도 된다 |
| `tags` | | 검색용 자유 태그. 없으면 생략 |
| `superseded_by` | `이력`·`폐기`면 ✅ | 이 문서를 대체한 문서의 경로. 대체 문서가 없으면 그 사유를 한 줄로 |

> 프론트매터는 렌더링에 방해되지 않는다 — GitHub 은 표로, Obsidian 은 속성 패널로 보여준다.
> `.prettierignore` 가 `*.md` 를 제외하므로 포매터가 이 블록을 재배치하지 않는다.

## 3. 영역 (space)

컨플루언스의 스페이스에 해당한다. **폴더를 옮겨서 표현하지 않는다** — 링크와 `git blame` 이 깨진다. 경로는 그대로 두고 속성과 인덱스로만 묶는다.

| 영역 | 무엇이 들어가나 | 경로 | 인덱스 |
|---|---|---|---|
| `프로젝트 기준` | 저장소 진입점·팀 규칙·문서 규약 | 루트 `*.md` · `docs/README.md` · `docs/CONVENTIONS.md` | [README](README.md) |
| `전략·제품` | 포지셔닝·경쟁·PRD·페르소나·로드맵·열린질문·가설 | `docs/00`~`06` | [README](README.md#전략제품) |
| `설계·개발` | IA·데이터플로우·개발 스펙·구현 현황·배포 | `docs/07`~`11` · `deploy-runbook` · `setup-supabase` | [README](README.md#설계개발) |
| `화면 스펙` | 화면 단위 기획서·제품 스펙·프로토타입 | `docs/specs/**` | [specs/README](specs/README.md) |
| `의사결정` | ADR — 되돌리기 어려운 결정의 기록 | `docs/decisions/**` | [decisions/README](decisions/README.md) |
| `리서치` | 시장·경쟁·법규·데이터 조사, 시뮬레이션 | `docs/research/**` (ut-agent 제외) | [research/README](research/README.md) |
| `검증·실험` | UT·실험 설계와 결과 | `docs/experiments/**` · `docs/research/ut-agent/**` | [experiments/README](experiments/README.md) |
| `디자인` | 디자인 시스템·로고 규칙·와이어프레임·카피 | `design/**` | [design/README](../design/README.md) |
| `발표·공유` | 발표 덱·대본·외부 공유물 | `docs/presentation/**` · `docs/리뷰용 문서/**` | [presentation/README](presentation/README.md) |

## 4. 상태 (status)

**판단 기준은 "지금 이걸 믿고 일해도 되는가" 하나다.**

| 상태 | 뜻 | 이럴 때 |
|---|---|---|
| **정본** | 지금 이 주제의 기준. **다른 문서와 어긋나면 이쪽이 맞다** | 한 주제에 정본은 하나다. 둘이면 하나를 `이력`으로 내린다 |
| **초안** | 썼지만 확정 아님. 참고는 하되 근거로 쓰지 않는다 | 화면 기획서 다수가 여기 |
| **이력** | 그 시점의 사실 기록. **틀리지 않았지만 현재 기준이 아니다** | 시뮬레이션 결과·발표 대본·지난 스프린트 계획표 |
| **폐기** | **현재 기준과 충돌한다.** 읽으면 잘못된 판단을 하게 된다 | 구 팔레트 문서·대체된 스펙. `superseded_by` 필수 |

> **`폐기` 는 보수적으로 쓴다.** 확신이 없으면 `이력`이다. 폐기는 "낡았다"가 아니라 "지금 기준과 부딪힌다"일 때만.
> **이력·폐기 문서를 지우지 않는다.** 왜 그렇게 결정했는지가 거기 남아 있다.

## 5. 링크

- **`docs/` 안에서는 `[[위키링크]]`** 를 쓴다. 확장자 없는 경로(`[[04-roadmap]]` · `[[decisions/DECISIONS]]` · `[[../design/README]]`).
- **폴더 밖·루트 문서로 나갈 때는 상대경로 마크다운 링크**(`[CONTRIBUTING](../CONTRIBUTING.md)`).
- 링크 대상이 실재하는지는 `npm run docs:check` 가 검사한다.

## 6. 넘버링

- `docs/` 두 자리 = **읽는 순서**. `00` 포지셔닝에서 시작해 `11` 배포로 끝난다. 새 주제는 뒤에 붙인다.
- `docs/specs/` 두 자리 = **3축 라인**(작성 순서 아님). `00` 진입 셸 · `01` 진단 리포트 · `02` 스튜디오 · `03` 커머셜·계정 · `04` 운영.
- `docs/decisions/` = `YYYY-MM-DD-주제.md`. 표 정본은 [DECISIONS.md](decisions/DECISIONS.md), 개별 파일은 그 행의 상세다.

## 7. 새 문서를 만들 때

1. 어느 **영역**인지 정하고 그 폴더에 만든다.
2. 위 프론트매터를 채운다. 확정 전이면 `status: 초안`.
3. **해당 영역 인덱스에 한 줄 등재한다.** 등재되지 않은 문서는 `docs:check` 가 "고아 문서"로 잡는다.
4. 되돌리기 어려운 결정이 포함되면 [DECISIONS.md](decisions/DECISIONS.md) 에 한 행 남기고 문서를 링크한다.

## 8. 문서를 내릴 때

**지우지 않는다.** 다음 두 줄만 바꾼다.

```yaml
status: 폐기
superseded_by: docs/specs/01-report-spec.md
```

그리고 본문 맨 위에 한 문장으로 **무엇이 왜 바뀌었는지** 남긴다. 대체 문서가 없다면 `superseded_by` 자리에 사유를 쓴다(예: `기능 자체가 제품에서 빠짐 — 2026-07-16 검수 제거`).

## 9. 검사

```bash
npm run docs:check
```

1. 모든 `.md` 에 프론트매터와 필수 키가 있는가
2. `status` 가 허용값인가 · `이력`·`폐기`에 `superseded_by` 가 있는가
3. `[[위키링크]]` 와 상대경로 링크의 대상이 실재하는가
4. 어느 인덱스에도 등재되지 않은 **고아 문서**가 있는가
