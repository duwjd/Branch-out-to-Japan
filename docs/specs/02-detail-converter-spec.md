## 0. 자산 맵 — 이 기능이 로드하는 것

| 자산 | 역할 |
|---|---|
| `data/processed/detail-style-prompts.json` (v1.1.0) | **기능이 직접 로드하는 블록 팩** — 블록 27종 정의·슬롯·법적 가드, 템플릿 6종(블록 시퀀스), 조건부 레이어 3종, 무드 프로파일, AI 블록별 제품 노출 정책(`productPresence`) |
| `app/fonts/jp/NotoSansJP-{Regular,Bold}.otf` | 상세페이지의 **모든 문자를 그리는 폰트**. satori 에 Buffer 로 직접 주입 (SIL OFL) |
| `docs/research/jp-detail-style-taxonomy.md` | 템플릿 6종·블록 27종의 정의·경계 규칙·실측 근거 |
| `data/processed/detail-ocr.jsonl` (v2) | 라쿠텐·Qoo10·아마존JP 상세 이미지 OCR + 블록 라벨 — 분류 근거 |
| `docs/research/jp-detail-message-patterns.md` §4 | 루브릭 A~E 18항목 — 블록 카탈로그가 전수 커버한다 |
| 이 문서 | 파이프라인 절차·조립 알고리즘·워크드 예시·검증 계획 |

### 관통 원칙 3개

**1. 메시지 재설계 도구다.** 범용 이미지 생성툴이 아니다(금지 포지션 1번과의 경계선). 카피는 번역이 아니라 일본 고객 관점의 재설계이며, 근거 없는 배지·가격·효능 주장은 프롬프트 진입 자체가 불가하다.

**2. 근거가 없으면 그 블록이 없는 페이지가 나오는 것이 정상 동작이다.** 블록 제외는 실패가 아니라 기본값이다. 다만 **왜 빠졌는지**를 항상 사용자에게 말한다(확인 화면 CONFIRM-02).

**3. 문자는 AI가 그리지 않는다.** AI는 글자 없는 배경컷만 만들고, 캐치카피를 포함한 모든 문자는 satori 가 벡터로 렌더한다. 이것이 이 기능의 **구조적 차별점**이다 — 썸네일(콜⑥)에서는 "오탈자 없음"이 프롬프트 부탁이었지만, 여기서는 사실이다.

> **왜 그렇게 했는가:** 확산 모델의 CJK 글리프 정확도는 문자 수에 대해 곱셈으로 떨어진다. 글자당 99%를 가정해도 20자는 82%, 200자는 사실상 0%다. 썸네일은 카피 2~3줄이라 통했지만 상세페이지는 블록당 200~600자다. 게다가 `※効能評価試験済み` 같은 근거 표기는 **한 글자만 어긋나도 근거로서 무효**가 되고 그게 곧 법적 리스크다.

## 1. 목표 · 비목표

**목표**
1. 제품컷(+한국 상세 원본)을 입력받아, 상세페이지 요소를 **블록 단위 이미지로 만들고 세로로 이어붙인** 완성 이미지를 낸다.
2. 상품 종류에 따라 이미지 분위기가, **프로모션 유무·옵션 개수에 따라 구성이** 달라진다.
3. 법적 가드(景表法·薬機法 인접 영역)가 **구조적으로** 작동한다 — 코드가 게이트를 소유한다.
4. 실제 일본 쇼핑몰에 그대로 올릴 수 있다 — 몰별 규격에 맞춘 **분할본**을 함께 낸다.

**입력 계약** (② DETAIL-02~06d 정본 · 파서: `lib/server/detailForm.ts`)

| 입력 | 필수 여부 | 대응 블록 | 비고 |
|---|---|---|---|
| 원본 이미지 1~10장 | **항상 필수** | B03·B24 외 | 첫 장 = 제품 대표컷. 나머지는 KR 상세 원본(위→아래 순서) |
| 상품 종류 | **필수** | 템플릿·무드 결정 | skincare/suncare/makeup/cleansing/haircare/etc |
| 타깃 플랫폼 | 선택 | 레이어 정책·출력 규격 | amazon-jp면 프로모 레이어 차단 |
| 템플릿 | **필수** | 블록 시퀀스 | D1~D6 |
| 제품 스펙(内容量·区分·販売元) | **항상 필수** | B26 | **약기법 표시 의무 — 원문 고정, 재가공 금지** |
| 성분 데이터(성분명·농도·목적) | 선택 | B09·B10 | 없으면 성분·기전 블록 제외. **성분명 창작 금지** |
| 무첨가·스펙 수치·사용법·주의사항 | 선택 | B16·B14·B22·B27 | |
| 실적 3필드 | 선택 | B04 | 3필드 **전부** 있을 때만 |
| 누적 판매 2필드 | 선택 | B05 | 수치+집계기간 쌍 |
| 시험 근거 4필드 | 선택 | B11·B12 | 시험명·기관·시점·n수 |
| 리뷰 원문 | 선택 | B25 | **실제 리뷰만. 후기 생성 금지** |
| 프로모(세트명·판매가 필수) | 조건부 | B01·B02 | `normalPriceVerified` 체크가 있을 때만 통상가 취소선 |
| 옵션(축·라벨·색상값) | 조건부 | B17~B21 | 2개 이상부터 블록 삽입 |
| 모델컷 + 사용 권한 동의 | 조건부 | B19 | 미동의 시 **해당 블록만** 제외(생성은 계속) |
| 추가 요청(자유 입력) | 선택 | AI 배경컷 | **이미지 분위기에만** 반영. 근거가 필요한 값은 받지 않는다 |

**비목표**
- 범용 상세페이지 빌더. 블록 카탈로그 밖의 자유 레이아웃은 제공하지 않는다.
- 카피 작문 대행 — 카피는 일본 관례·약기법 프레임 안에서 재설계하며, 사실은 입력에서만 온다.
- HTML 상세(라쿠텐 RMS) 산출 — v1은 이미지만. §6 열린 질문.
- 물리 패키지 현지화.

## 2. 파이프라인 7단계

```
analyze → plan  →  copy  →  blocks   →  compose  →  slice  →  gate
 (입력)   (결정적) (콜⑦ 1회)  (AI≤4 + satori)  (sharp)   (몰 규격)  (검수·각주정합)
```

### ① analyze — 입력 수집
업로드 이미지를 저장하고(순서 = 위→아래), 활성 브랜드·브랜드명 스냅샷을 물질화한다.

### ② plan — 블록 시퀀스 결정 (**LLM 미개입, 결정적**)
`planBlocks(input, platform, templateId, disabledBlocks)`:
1. 템플릿의 `blockSequence` 를 펼친다.
2. 조건부 레이어를 삽입한다 — 프로모·실적은 head, 옵션은 히어로 다음.
3. **게이트**: 각 블록의 `requires` 토큰을 입력에 대해 평가. 하나라도 미충족이면 **블록째 제거**하고 사유·해결힌트를 기록한다.
4. **AI 상한**: 이미지 생성 블록이 `MAX_AI_BLOCKS(4)` 를 넘으면 hybrid 는 text 로 강등, ai-visual 은 제외.
5. **법적 블록 고정**: `TEXT_ONLY_BLOCKS` 는 팩 값과 무관하게 `renderKind='text'`. 승격 불가.
6. 각주 블록을 항상 마지막으로.

> 같은 입력이면 같은 시퀀스가 나와야 하므로 이 단계에 LLM을 넣지 않는다. 확인 화면(CONFIRM)은 이 함수의 산출을 그대로 보여준다 — 화면이 따로 추론하지 않는다.

### ③ copy — 콜⑦ detailCopy (Claude 비전 1회)
블록별로 1콜씩 부르면 비용·시간이 폭발하므로 **전 블록 슬롯을 한 콜에** 채운다(`maxTokens: 12000`).
- system: `buildStableGrounding('detailCopy', category, '화장품')` — 일본 서사 원칙 + 번역 금지 + 코드 소유 값 산출 금지 + 약기법 프레임 + 렉시콘 20.
- 요청하는 것: `source:'llm'` 슬롯만. 가격·실적·시험·전성분은 **아예 요청하지 않는다**.
- 검증: 필수 슬롯 누락/공란이면 교정 지시 후 1회 재시도.

### ④ 슬롯 확정 — `assembleBlockSlots` (**법적 게이트**)
```
LLM 슬롯 중 팩에 source:'llm' 로 선언된 키만 채택   ← 월권 슬롯 제거
  ↓ 코드 소유 슬롯으로 덮어쓴다
가격     promo 입력만 자단위 조립. normalPriceVerified 아니면 통상가 빈 문자열
실적     proof 3필드 → 배지 + `※실적명（부문・집계일）`
시험     test 4필드 + 부인 문구 `すべての方に刺激が…`
성분     input.ingredients 만. 배합 목적 각주 자동
스펙표   区分·全成分 원문 그대로
각주     앞선 블록이 배출한 마커를 전부 수집
```
각주는 `FootnoteRegistry` 가 ※1..※n 을 발급하고, 마지막 각주 블록이 일괄 해소한다.

### ⑤ blocks — AI 배경컷 + satori 렌더
- AI 블록만 `generateBlockVisual()` — **동시성 4**(`limit()`). 순차면 이미지 5장에 200~450초로 `maxDuration=300` 을 넘고, 무제한 병렬은 429를 부른다.
- 프롬프트 negative 1순위: `No text, letters, kana, kanji, hangul, numbers, logos, or watermarks anywhere`.
- **AI 블록은 제품 노출 정책을 반드시 하나 갖는다**(팩 `productPresence`, 중간값 없음).
  - `source` (B03 히어로·B24 텍스처·B21 발색·B15 사용씬) — 업로드 원본을 `images.edit` 로 넘긴다.
  - `none` (B06 문제제기·B08 비교도해·B19 퍼스널컬러·B23 브랜드) — 프롬프트에 용기 등장 금지 문구를 붙인다.
  - 중간을 두지 않는 이유: 원본 없이 제품을 그리게 두면 모델이 매번 다른 용기를 지어내 **한 상세페이지에 서로 다른 제품이 섞인다**(2026-08-10 실측 — 비교 도해가 히어로와 다른 병을 그림). 정책을 팩이 소유해 잡 러너·CLI·블록 재생성 세 호출부가 어긋나지 않게 한다.
- `renderBlock()` — 배경컷을 `data:` URI 로 깔고 그 위에 flex 로 텍스트를 얹는다. **블록당 satori 1패스.**
- **높이 결정 규칙 2갈래**:
  - *텍스트 블록* — 넉넉한 캔버스(4000px)에 렌더하고 콘텐츠 뒤에 2px 마젠타 센티넬 바를 둔다. 좌측 4px 컬럼만 raw 로 훑어 y를 찾아 크롭. 센티넬을 못 찾으면 **실패시킨다**(조용히 잘린 블록은 각주가 사라진 것이라 위험하다).
  - *배경컷 블록* — **고정 높이 `VISUAL_BLOCK_HEIGHT(1500px)`**. 콘텐츠 높이로 줄이면 배경 사진의 윗부분만 남아 제품이 잘려 나간다(2026-08-10 실검증에서 실제로 발생). 사진이 그 높이를 채우고 텍스트 카드가 세로 중앙에 얹힌다. 생성 크기 `1024×1536`(≒2:3)와도 맞물린다.
- 블록마다 행 단위로 `status`·`imagePath`·`height` 를 기록하고 `blockDone` 을 원자 증가.

### ⑥ compose / ⑦ slice — sharp
- 블록 PNG를 세로 결합 → 출력 폭으로 다운스케일(업스케일 금지) → JPEG q88 mozjpeg.
- 플랫폼 프로파일대로 분할. 2MB 초과 슬라이스는 q88→80→72→64 재인코딩.
- `MAX_TOTAL_HEIGHT(18,000px)`·분할 장수 상한 초과 시 잘라내고 **사유를 게이트에 기록**한다(조용히 자르지 않는다).

### ⑧ gate — 검수 게이트
`noTypos`(벡터 렌더 — AI 미개입) · `labelPreserved` · `noUnprovenBadges`(제외 블록 수) · `footnoteIntegrity`(고아 각주 0) + 조건부 `promoValues`·`specVerbatim`·`truncated`.

## 3. 워크드 예시 (골든 픽스처)

`npm run detail:cli` — HARUON 스킨케어 / 프로모 있음 / 실적·시험 있음 / 옵션 없음, 라쿠텐.

```
템플릿 D1 · 블록 15개 · AI 블록 4개
포함: B01 몰 프로모 배너 → B02 세트·수량 오퍼표 → B04 랭킹·수상 스택 → B05 누적 판매·리뷰 수
    → B03 히어로 → B06 문제 제기 → B07 원인 구조화 → B08 비교 도해 → B09 기전 도해
    → B12 시험·근거 라벨 → B13 POINT → B24 텍스처 → B22 사용법 → B26 스펙표 → B27 각주
제외:
  - B21 발색·텍스처 시연: 색상 옵션이 2개 미만입니다. [옵션 정보]
  - B20 라인업 비교 차트: 비교할 라인업 옵션이 2개 미만입니다. [옵션 정보]
  - B18 컬러 차트 매트릭스: 색상 옵션이 6개 미만이라 차트 대신 칩만 넣었습니다.
  - B17 컬러 칩 그리드: 색상 옵션이 2개 미만입니다. [옵션 정보]
각주 정합: OK (등록 3 · 고아 0 · 미사용 0)
결합 1200x7177 → master 0.40MB · 분할 5장(최대 87KB)
```

**대조 케이스** (게이트가 플랫폼·근거 때문에 도는지 확인)

| 조건 | 결과 |
|---|---|
| 아마존JP + 프로모 입력 | **400** — "A+ 콘텐츠는 가격·프로모션 표기가 규정상 금지" |
| 아마존JP + 프로모 없음 | 6블록. B01·B02가 A+ 사유로 제외 |
| 색조 + 색상 8개 | 7블록. **B17 컬러칩 → B18 차트 매트릭스 → B21 발색 시연**이 단계적으로 삽입 |
| 성분 미입력(D2) | B10·B09 제외 — "성분명을 지어내지 않습니다" |
| 실적 3필드 중 집계일 공란 | B04 제외 — 부분 입력은 인정하지 않는다 |

## 4. 생성물 품질 체크리스트 + 목 모드 계약

- [ ] 입력 제품컷 기반인가 (원본이 결과 화면에 병기되는가)
- [ ] 제품 형상·라벨이 원본과 동일한가 (패키지 인쇄 문자는 AI가 재생성하는 영역 — §6 Q5)
- [ ] **한 페이지에 서로 다른 제품이 섞이지 않았는가** ← `productPresence` 가 구조적으로 차단 (§2)
- [ ] **일본어 오탈자·유령 글자가 없는가** ← 벡터 렌더라 구조적으로 보장
- [ ] 한글·간체자·이모지가 없는가 ← `uncoveredGlyphs()` 가 생성 전 차단
- [ ] **제공하지 않은 배지·순위·가격·시험결과·그래프·리뷰가 생성되지 않았는가** ← 최우선

## 6. 열린 질문

- **Q1. HTML 상세(라쿠텐 RMS) 산출을 지원할 것인가.** 이미지만으로는 SEO·접근성이 약하다. 블록 구조가 이미 있어 HTML 출력은 어렵지 않으나, 몰별 허용 태그가 다르다.
- **Q2. 전성분 원문 확보 경로.** 현재는 사용자 직접 입력이다. ① 리포트 입력에서 재사용하거나 브랜드 자산으로 승격할 수 있다.
- **Q3. 블록 순서 재정렬(생성 후).** v1은 확인 화면에서 on/off만 지원한다. 생성 후 드래그 재정렬은 `asset_blocks.seq` 갱신 + recompose 로 가능하나 UI 비용이 있다.
- **Q4. 비용 모델.** 건당 약 $0.42(이미지 4콜 $0.25 + Claude $0.17). 텍스트 블록 재생성은 $0. `OPENAI_IMAGE_QUALITY=low` 로 이미지 비용을 1/4로 낮출 수 있다.
- **Q5. 제품 패키지 인쇄 문자는 여전히 AI 손에 있다.** 2026-08-11 원본 대조 결과 `images.edit` 는 라벨을 **정확히 보존**했다 — 원본 `rakuten_tvert_352.jpg` 의 `TOUT VERT / BALANCING GA / LOTION`, 하단 영문 4행, `100mL 3.5fl.oz.` 가 히어로·텍스처 두 블록에서 자단위로 재현됐다(2블록/1제품 표본). 8/10에 기록했던 `BALANCING GEL LOTION` → `GA` 변형은 **원본 대조 없이 단정한 오기**로, 원본이 처음부터 `GA`였다. 다만 라벨이 생성 대상인 구조 자체는 그대로이므로 표본을 넓히기 전까지 검수 게이트 문구는 유지한다. 근본 해법(배경만 생성 + 원본 제품컷 sharp 합성, 누끼·배치 로직 필요)은 라벨 열화가 실제로 관측될 때 착수한다.
- **Q6. Storage 정리.** 건당 블록 10~15 + 슬라이스 12 + 마스터 1 = 약 25파일. 브랜드 삭제 시 DB만 cascade되고 Storage는 남는다.
