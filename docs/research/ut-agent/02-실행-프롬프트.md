# AI 에이전트 UT — Claude Code 실행 프롬프트

> 계획: [00-ut-plan](00-ut-plan.md) · 산출물 형식: [01-산출물-형식](01-산출물-형식.md)
> **사용법:** 아래 블록을 순서대로 Claude Code에 붙여넣는다. `{{...}}`만 바꾼다. 각 프롬프트는 앞 단계가 끝난 상태를 전제한다.
> **대상은 배포본이다.** `BASE_URL = https://branch-out-to-japan.vercel.app` — 로컬 dev 서버를 쓰지 않는다.
> **비용 경고:** 실제 LLM·이미지 API를 호출한다. 20명 × (리포트+썸네일+상세) = **이미지 106~146콜**. 파일럿(P5)에서 **실단가를 측정하고 20명 견적을 승인받기 전에는** 배치를 돌리지 않는다.

## P0 — 배포본 환경 점검

```
YOAKE 실서비스에 대한 AI 에이전트 UT를 시작한다. 대상은 배포본이다.
BASE_URL = https://branch-out-to-japan.vercel.app

docs/research/ut-agent/00-ut-plan.md 를 읽고 §4-1 배포본 전제 6항을 점검해라. 로컬 dev 서버는 띄우지 마라.

1. BASE_URL 이 200을 주는지, 랜딩이 정상 렌더되는지 확인해라. 콜드스타트 지연도 재서 보고해라
2. Supabase 프로젝트가 자동 pause 되지 않았는지 확인해라 — 7일 무활동이면 멈춘다.
   로그인/조회 API가 5xx 를 주면 pause 를 의심하고, 대시보드 restore 가 필요하다고 보고해라
3. AUTH_MAIL_MODE=devlink 가 켜져 있는지 확인해라 — 확인 방법은 test99@example.com 같은 더미로 signup 을 한 번 때려
   응답에 devLink 가 오는지 보는 것이다. 안 오면 계정 20개를 만들 수 없으니 Vercel 환경변수 설정이 먼저다
4. GET /api/studio/detail 로 실행 모드 메타를 확인해라 — imageMode 가 real 인지, LLM_MODE·IMAGE_MODE 목 스위치가 꺼져 있는지.
   목 모드면 산출물 평가가 통째로 무효라는 걸 경고해라
5. 상세페이지 프리플라이트 상태를 확인해라. POST /api/studio/detail 이 503 을 주면 응답의 readiness 를 읽고
   마이그레이션·JP폰트·Storage 버킷·키 중 무엇이 빠졌는지 보고해라
6. .ut/accounts.json 의 20개 계정에 대해 POST /api/auth/email/login 이 200인지 확인하고,
   로그인 성공 / 미인증(403) / 미가입(401) 3분류로 세어서 표로 보고해라

키 값·비밀번호는 절대 출력하지 마라. 아직 코드는 만들지 마라.
6항 중 하나라도 막히면 원인과 조치를 제시하고 거기서 멈춰라.
```

## P1 — 계정 20개 프로비저닝 (멱등)

```
docs/research/ut-agent/00-ut-plan.md §4-1 에 따라 UT 계정 20개를 준비해라.
계정은 .ut/accounts.json 에 있다 (P01→test01@example.com … P20→test20@example.com). 비밀번호는 그 파일에만 있고 저장소·로그 어디에도 적지 않는다.

scripts/ut/provision-accounts.mjs 를 만들어라. 동작은 이렇다. 페르소나마다 순서대로:
  1) POST /api/auth/email/signup { email, password, name: 페르소나 브랜드명 }
     - 200 이면 응답의 devLink 에서 ?token= 값을 뽑아 POST /api/auth/email/verify { token } 호출
     - 409("이미 가입된 이메일") 면 건너뛴다
  2) POST /api/auth/email/login { email, password } 으로 최종 확인
     - 403 { code: 'unverified' } 면 POST /api/auth/email/resend 후 devLink 로 다시 verify 하고 재시도
  3) 결과를 .ut/accounts-status.json 에 기록 (email, created|existed, verified, loginOk)

주의
- devLink 는 비-운영이거나 AUTH_MAIL_MODE=devlink 일 때만 내려온다(lib/server/mailer.ts). 안 내려오면 그 사실을 명확히 보고하고 멈춰라
- 비밀번호·토큰을 로그에 남기지 마라
- console.log 금지 (CLAUDE.md) — 진행 출력은 process.stdout.write 를 써라

실행 후 20행 결과표를 보여줘라. 전부 loginOk=true 가 아니면 다음 단계로 넘어가지 마라.
```

## P2 — 페르소나 입력 fixture 생성

```
docs/research/ut-agent/00-ut-plan.md §8 매핑 규칙에 따라
docs/research/ut-agent/fixtures/personas-input.json 을 20건 만들어라.

원본은 .claude/agents/persona_01.md ~ persona_20.md 다. 페르소나 데이터를 요약·변형하지 말고 그대로 근거로 삼아라.

각 항목에 담을 것
  account          : test{nn}@example.com
  brand            : brandName, category(skincare|makeup|suncare|cleansing), positioningTags[], positioningNote, channels
  report           : productName, productClass, ingredients, price, detailContent, expectedMode(brand|brandProduct)
  thumbnail        : styleId(A~H), platform, proof(있으면 rankTitle·genre·aggregationDate)
  detail           : templateId(D1~D6), productCategory(skincare|suncare|makeup|cleansing|haircare|etc),
                     specVolume, specCategory, specManufacturer, specOrigin?, specFullIngredients?, promo?

규칙
- positioningTags 는 lib/engine/rules/positioning.ts 의 16종 value 중에서만 고른다. 주석에 어느 페르소나에서 유래했는지 적혀 있으니 그대로 따르면 된다
- detailContent 는 §8-2 의 3군(충분 200자+ / 빈약 50~200자 / 없음)으로 나눈다. 소속은 §8-2 표 그대로 지켜라
- detailContent 원문은 그 브랜드가 "한국에서 실제로 쓰던 상세 카피"처럼 읽혀야 한다. 일본어를 넣지 마라
- styleId A~H 8종과 templateId D1~D6 6종이 20명에게 고루 분산되게 배정해라. 페르소나 컨셉과 안 맞는 배정은 하지 마라
- specVolume·specCategory·specManufacturer 는 상세페이지 필수 3항이다(lib/server/detailForm.ts). 반드시 채워라
- P05 는 아마존JP 라 promo 를 넣으면 400 이다. 일부러 넣어서 에러 문구 반응을 볼지, 뺄지는 §8-4 를 따라라
- P18 은 productCategory=haircare, P20 은 etc 다

만든 뒤 표로 요약해서 보여줘라: 페르소나 / 카테고리 / 진단 모드 / styleId / templateId / detailContent 군.
```

```

## P5 — 파일럿 (P01 전 과업) + **비용 실측 게이트**

```
P01(글로우리프·김서연 / test01@example.com)로 UT 파일럿을 배포본에서 돌린다.

node scripts/ut/capture.mjs --persona P01 --tasks T0,T1,T2,T3,T4,T5,T6,T7 --base https://branch-out-to-japan.vercel.app

끝나면 .ut/runs/P01/manifest.json 을 읽고 보고해라
  - 과업별 실측 소요 (T0 랜딩 스크롤 포함)
  - generations 3종이 전부 성공했는지 (report published / thumbnail done / detail done)
  - 상세의 aiCuts 와 degradedCuts — 강등이 있었으면 배포본 실행이 시간 예산에 눌렸다는 뜻이다
  - 캡처 누락 스텝 · 콘솔 에러 · 실패 요청
  - artifacts 가 전부 내려왔는지

그 다음 **이미지 비용을 실측해서 20명 견적을 확정해라.**
  1) manifest 의 imageCost 와 각 이미지 콜의 usage 를 표로 보여줘라 (콜별 size·quality·input/output 토큰·USD)
  2) 썸네일 장당·상세 배경컷 장당 실단가를 뽑아라
  3) 20명 견적을 다시 계산해라:
       썸네일 20콜 + 상세 (실측 장수 × 20) + 제품컷 6콜 + 재시도 여유 20%
  4) 계획서 §10-2 의 실측 단가와 대조해라 — generate 1024x1536 = $0.0420, edit 1024x1024 = $0.0652.
     이번에 새로 알게 되는 건 **1024x1536 edit(상세 히어로컷) 단가**다. 계획서는 $0.055 로 가정했다
  5) OpenAI 대시보드 사용량과도 대조해라 (계기가 맞게 계산하는지 검증)
