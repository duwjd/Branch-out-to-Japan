# AI 에이전트 사용자 테스트(UT) 계획 — YOAKE 실서비스 만족도 평가

> **한 줄:** 합성 페르소나 20인(`persona_01`~`persona_20`)이 **배포된 YOAKE**(https://branch-out-to-japan.vercel.app)에 들어가 랜딩을 먼저 평가하고, 각자의 계정으로 로그인해 브랜드를 등록한 뒤 **진단 리포트·썸네일·상세페이지를 각 1회씩 실제로 생성**하고, 과업 성공·이탈 지점·산출물 만족도·지불의향을 평가한다.
> **자극물은 작동하는 배포본 그 자체다.** 2026-07 시뮬레이션은 랜딩 시안 HTML이 자극물이었다. 이번엔 실제 서비스다.
> 관련: 페르소나 정의 [.claude/agents/persona_01.md](../../../.claude/agents/persona_01.md) · 구현 현황 [10-implementation-status](../../10-implementation-status.md) · 배포 스펙 [11-deploy-spec](../../11-deploy-spec.md) · 이전 시뮬 [시뮬레이션-리포트](../simulations/시뮬레이션-리포트.md)

**변경 이력**
- 2026-08-20 ① 공용 계정 1개 → **페르소나별 개별 계정 20개**. 격리 절차 소멸, 병렬 실행 가능. 생성 과업을 전원 3종으로 확대.
- 2026-08-20 ② **로컬 dev → 배포본(Vercel) 확정.** **T0 랜딩페이지 평가 신설**(매력도·흥미도). **§10 이미지 API 비용 측정** 신설.

## 1. 이 테스트가 답해야 할 질문

| # | 질문 | 판정 지표 |
|---|---|---|
| **Q0** | **랜딩페이지가 매력적이고 흥미로운가** — 로그인 전에 이미 마음이 움직이는가 | T0 매력도·흥미도 1~5, 3초 첫인상, 스크롤 이탈 지점 |
| Q1 | 처음 들어온 브랜드가 **혼자 힘으로 첫 진단 리포트까지 도달**하는가 | T3 과업 성공률, 이탈 스텝 |
| Q2 | 나온 **리포트가 "내 브랜드 얘기"로 읽히는가**, 아니면 일반론인가 | 산출물 정확성 1~5 |
| Q3 | 산출물이 **번역·범용 생성툴과 다르다고 느껴지는가** (핵심 차별점 검증) | 차별성 1~5 + 근거 인용 |
| Q4 | **돈을 낼 것인가** — 각자의 가격 수용도 안에서 실제 지불 의사가 서는가 | WTP Y/N + 금액 + 이유 |
| Q5 | **AI 거부감군(P05·P13·P19·P20)** 이 어디서 등을 돌리는가 | AI 저항 트리거 스텝 |
| Q6 | **품의형(P08·P10·P14·P15·P17)** 이 이 화면으로 사내 결재를 올릴 수 있는가 | 품의 가능 Y/N + 부족한 재료 |
| Q7 | 생성 **대기시간**(리포트 2~3분 · 썸네일 1~2분 · 상세 150~185초)을 견디는가 | 실측 대기 초 + 대기 중 반응 |
| Q8 | 3축(진단·스튜디오·운영)이 **하나의 서비스로 연결돼 보이는가** | T6·T7 |
| Q9 | **진단 결과가 제작의 입력값이 되는 폐루프**가 사용자에게 체감되는가 | T4·T5에서 리포트 참조 인식 여부 |

### 이 테스트가 답하지 못하는 것 (선언)
- 합성 페르소나는 실제 고객이 아니다. **실제 구매 행동을 예측하지 않는다.**
- 모델은 그럴듯한 답을 지어낼 수 있고, **긍정 편향**이 기본값이라 프롬프트로 억제해도 남는다.
- 미적 선호(색·타이포)는 신뢰하지 않는다. **읽히는가·이해되는가·다음 행동이 보이는가**만 신뢰한다.
- 따라서 **"실사용자 UT 전 사전 스크리닝"** 으로만 쓴다.

## 2. 참가자 — 20인 · 계정 1:1

**페르소나 P{nn} = 계정 `test{nn}@example.com`** — 비밀번호는 저장소에 적지 않는다. 계정·비밀번호 매핑은 `.ut/accounts.json`(git 제외)에만 둔다

| 아키타입 | 페르소나 | 계정 | 이 UT에서 보는 것 |
|---|---|---|---|
| **A. 입점직전 인디대표** (8) | P01~P08 | test01~08 | 랜딩 흥미도 · 온보딩 이탈 · 첫 리포트 도달 · 30~50만 원대 WTP |
| **B. 정체돌파 운영자** (6) | P09~P14 | test09~14 | 리포트가 "정체 원인"을 짚는가 · 재진단 니즈 |
| **C. 콘텐츠 리소스 부재형** (4) | P15~P18 | test15~18 | 썸네일·상세페이지가 실제로 일손을 덜어주는가 |
| **D. 신중한 첫도전자** (2) | P19~P20 | test19~20 | 무료 구간에서 어디까지 가치를 느끼고 어디서 이탈하는가 |

**교차 렌즈 (아키타입과 직교 — 별도로 집계한다)**
- AI 거부감: P05 · P13 · P19 · P20 → "AI 기반" 표현·자동 생성 티가 나는 지점 색출
- 품의 필요: P08 · P10 · P14 · P15 · P17 → 결재 근거로 쓸 화면·문서가 있는가
- 일본어 불가: P12 · P17 · P19 · P20 → 일본어 산출물을 **검증할 수 없는** 사용자의 신뢰 형성 경로

> **개별 계정이 만든 차이:** 계정당 브랜드 1개 제한([app/api/brand/route.ts:114](../../../app/api/brand/route.ts#L114))과 자산 삭제 API 부재가 더 이상 문제가 되지 않는다. 각자 **자기 계정의 빈 라이브러리에서 출발**하므로 온보딩·빈 상태 반응이 유효하다.

## 3. 아키텍처 — 역할 4종

에이전트가 브라우저를 직접 조작하지 않는다. **드라이버가 조작하고, 페르소나는 화면을 본다.** 페르소나 에이전트는 `Read` 도구만 갖고 있으므로 모든 화면을 **파일로 물질화**해서 건넨다. `Read`는 PNG를 시각적으로 읽으므로 페르소나는 실제 화면을 **본다**.

```
┌ 모더레이터 (메인 Claude Code 세션) ─────────────────────────┐
│  계정 프로비저닝 · 실행 관리 · 비용 계측 · 무효 판정        │
└───────┬──────────────────────────────────┬──────────────────┘
        │ Bash                             │ Agent
        ▼                                  ▼
┌ 드라이버 (Playwright) ────────┐   ┌ 참가자 (persona_NN) ─────┐
│ scripts/ut/capture.mjs        │   │ tools: Read 만           │
│ → https://branch-out-to-      │   │ - screens/*.png 을 본다  │
│   japan.vercel.app            │──▶│ - 페르소나 목소리로 반응 │
│ - T0 비로그인 랜딩 캡처       │   │ - 다음 행동을 1줄로 지시 │
│ - T1~T7 계정 로그인 후 실행   │◀──│   (Track B 턴제일 때)    │
│ - PNG + TXT + 소요초 + 에러   │   └──────────────────────────┘
└───────────────────────────────┘              │
                                               ▼
                                    ┌ 분석가 (general-purpose) ┐
                                    │ 20건 로그 → 종합 리포트  │
                                    └──────────────────────────┘
```

**격리 원칙:** 페르소나 에이전트는 **자기 폴더(`.ut/runs/{PID}/`)만** 읽는다. 다른 페르소나의 응답·본 계획서·기획 문서를 읽히지 않는다. 자기가 평가 대상이라는 사실도 알리지 않는다.

## 4. 실행 환경 — 배포본

| 항목 | 값 |
|---|---|
| **BASE_URL** | **`https://branch-out-to-japan.vercel.app`** |
| 호스팅 | Vercel Hobby (Fluid Compute · 함수 상한 **300초**) |
| 저장소 | Supabase Free (DB 500MB · Storage 1GB · Egress 5GB/월) |
| LLM | `ANTHROPIC_API_KEY` — 실 모드 (목 픽스처로 평가하면 결과가 거짓이 된다) |
| 이미지 | `OPENAI_API_KEY` · `gpt-image-2` · `OPENAI_IMAGE_QUALITY=medium` |

> 로컬 `npm run dev`는 쓰지 않는다. **평가 대상은 실사용자가 접속하는 그 화면과 그 속도**다. 콜드스타트·서버리스 예산·Storage 서빙이 모두 결과에 포함되는 것이 이 결정의 목적이다.

### 4-1. 배포본 전제 점검 (UT 시작 전 필수)

| # | 확인 | 안 되면 |
|---|---|---|
| 1 | **Supabase 자동 pause 해제** — 7일 무활동 시 프로젝트가 멈춘다([11-deploy-spec §2](../../11-deploy-spec.md)) | 전 과업 실패. 대시보드에서 restore 후 시작 |
| 2 | **`AUTH_MAIL_MODE=devlink`** 설정 여부 | signup 응답에 `devLink`가 안 와서 계정 20개를 만들 수 없다([lib/server/mailer.ts:27](../../../lib/server/mailer.ts#L27)) |
| 3 | **Fluid Compute 활성** — off면 함수 상한이 60초 | 리포트·상세 파이프라인이 전부 타임아웃 |
| 4 | **상세페이지 프리플라이트** — 마이그레이션·JP 폰트·Storage 버킷([detailReadiness.ts](../../../lib/server/detailReadiness.ts)) | `POST /api/studio/detail` 503 → T5 20건 전멸 |
| 5 | **Storage 여유** — 상세 3.09MB/건 × 20 ≈ 62MB + 썸네일·리포트 | 1GB 대비 여유. 기존 사용량만 확인 |
| 6 | **`LLM_MODE`·`IMAGE_MODE` 미설정** — 목 강제 스위치가 켜져 있으면 안 된다 | 산출물 평가가 통째로 무효 |

### 4-2. 계정 프로비저닝 (멱등)
20개 계정이 **존재하고 이메일 인증까지 끝나 있어야** 한다. `POST /api/auth/email/login`은 미인증 계정에 403 `{code:'unverified'}`를 준다.

```
for nn in 01..20:
  POST /api/auth/email/signup { email: test{nn}@example.com, password: <.ut/accounts.json 의 값>, name: "{브랜드명}" }
    → 200 { ok, devLink }  … devLink 의 ?token= 을 뽑아
       POST /api/auth/email/verify { token }   → 인증 완료
    → 409 "이미 가입된 이메일"                 … 이미 있음, 건너뛴다
  POST /api/auth/email/login { email, password } → 200 이면 준비 완료
                                                 → 403 unverified 면 resend 후 재시도
```
**20행 로그인 성공 결과표를 확보하기 전에는 UT를 시작하지 않는다.**

썸네일은 제품 이미지 1장 **필수**([thumbnail/route.ts:30](../../../app/api/studio/thumbnail/route.ts#L30)), 상세페이지는 **제품컷 1장이 별도 필수**(KR 상세 원본은 선택).

### 4-4. 동시 실행 정책 — **상세페이지는 순차**

| 과업 | 동시 실행 |
|---|---|
| T0~T2 (랜딩·로그인·브랜드 등록) | **4명 동시** — 생성 호출 없음 |
| T3 리포트 · T4 썸네일 | **2명 동시** |
| **T5 상세페이지** | **1명씩 순차** |

상세 잡 하나가 내부적으로 **이미지 6장을 동시성 6으로 한 웨이브**에 돌린다([output.ts `IMAGE_CONCURRENCY=6`](../../../lib/studio/detail/output.ts)). 2건을 겹치면 순간 12콜이라 OpenAI 429 확률이 급등하고, 더 나쁜 것은 **[budget.ts](../../../lib/studio/detail/budget.ts)가 남은 시간을 재서 우선순위 낮은 컷부터 텍스트로 강등**한다는 점이다. 즉 **동시 실행이 산출물 품질을 조용히 떨어뜨린다** — 평가 대상이 오염된다. 20건 순차 ≈ 55~62분이면 감당할 수 있는 값이다.

## 5. 2트랙 설계

### Track A — 과업 기반 UT (전원 20명, 필수)
드라이버가 정해진 스텝을 끝까지 실행해 화면 시퀀스를 캡처한 뒤, 페르소나가 한 번에 읽고 평가한다.

### Track B — 자유 탐색 UT (6명, 턴제)
과업 지시 없이 **"일본 진출 준비를 해보라"** 만 주고, 페르소나가 매 턴 다음 행동 1개를 지시하면 드라이버가 집행한다. 최대 15턴 또는 `STOP`까지.
- 대상: **P03**(급한 대표) · **P05**(AI 거부) · **P10**(품의·불신) · **P13**(AI 거부·사람 신뢰) · **P15**(콘텐츠 부재·품의) · **P19**(무료만). `model: opus`로 승격.
- **Track A보다 먼저 돌린다** — Track A가 끝난 계정은 브랜드·자산이 이미 있어 "첫 방문"이 아니다.

## 6. 과업 시나리오 (T0~T7)

각 과업은 **성공 조건**과 **관찰 포인트**를 함께 갖는다. 페르소나에게는 성공 조건을 알려주지 않는다.

### T0 — 랜딩페이지 평가 (전원, **비로그인**)
`https://branch-out-to-japan.vercel.app/` 를 처음부터 끝까지 스크롤. **로그인하지 않는다.** 이 과업만 별도 캡처 세트로 남긴다(뷰포트 단위 순차 캡처 + 전체 fullPage 1장).

- **묻는 것 (2026-07 랜딩 시뮬과 같은 5항 — 직접 비교하기 위해 형식을 맞춘다)**
  1. **3초 첫인상** — 스크롤 전, 히어로만 보고 든 생각
  2. **카피 이해도** — 이 서비스가 뭘 해준다는 건지 내 말로 설명
  3. **페인포인트 연관성** — 내 상황과 맞는가
  4. **다음 행동 의향** — 로그인/신청까지 갈 마음이 드는가 (N/5)
  5. **이탈 포인트** — 어느 섹션에서 창을 닫았을 것 같은가
- **추가로 이번에 새로 묻는 것**
  - **매력도 1~5** — 보기 좋고 믿음이 가는가 (첫인상·완성도)
  - **흥미도 1~5** — 더 읽고 싶어지는가 (끝까지 스크롤할 동기)

### 10-2. 단가 — **실측 완료** (2026-08-20)

제품컷을 만들면서 OpenAI 응답의 `usage` 를 그대로 받아 계산했다. 원장은 [fixtures/products/usage.json](fixtures/products/usage.json).

| 호출 | 크기 | 품질 | 입력 토큰 | 출력 토큰 | **실측 장당** |
|---|---|---|---|---|---|
| `images.generate` | 1024×1536 | medium | 텍스트 ~172 | 1372 | **$0.0420** |
| `images.edit` | 1024×1024 | medium | 이미지 1536 + 텍스트 46 | 1756 | **$0.0652** |

토큰 단가 (gpt-image-2, [OpenAI API Pricing](https://developers.openai.com/api/docs/pricing) 확인 2026-08-20):
이미지 입력 **$8/1M** · 캐시된 이미지 입력 $2/1M · 텍스트 입력 **$5/1M** · 출력 **$30/1M**

`비용 = (이미지입력×8 + 캐시입력×2 + 텍스트입력×5 + 출력×30) ÷ 1,000,000`

> **`images.edit` 가 `generate` 보다 비싸다.** 입력 이미지 토큰(1536)이 붙고, gpt-image-2가 입력을 항상 고정밀 처리해 출력 토큰(1756)도 generate(1372)보다 많다. **썸네일 1장이 상세 배경컷 1장보다 비싸다** — 직관과 반대라 견적에서 자주 틀리는 지점이다.

**20명 견적 (실측 기반)**

| 항목 | 콜 | 장당 | 소계 |
|---|---|---|---|
| 썸네일 T4 (`edit` 1024×1024) | 20 | $0.0652 | $1.30 |
| 상세 배경컷 T5 — `edit` 히어로 1장/건 | 20 | ~$0.055 † | $1.10 |
| 상세 배경컷 T5 — `generate` 나머지 3~5장/건 | 60~100 | $0.0420 | $2.52~4.20 |
| 재시도·블록 재생성 여유 +20% | | | $0.98~1.32 |
| **앞으로 쓸 것** | **100~140콜** | | **≈ $5.9~7.9 (약 8천~1.1만 원)** |
| 이미 쓴 것 (제품컷 5 + 프로브 1) | 6콜 | | $0.275 |
| **총계** | | | **≈ $6.2~8.2** |

† 1024×1536 `edit` 는 미측정이다. `generate` $0.0420 + 이미지 입력 1536토큰×$8/1M($0.0123) ≈ $0.054로 잡았고, 출력 토큰이 edit에서 늘어나는 경향을 감안해 $0.055로 둔다. **파일럿 P01 1건에서 확정한다.**

### 10-3. 앱 안에서도 계기를 단다 (잔여)

제품컷 스크립트는 `usage` 를 직접 받아 기록했지만, **앱 코드는 아직 이미지 응답의 `usage` 를 버린다.** [lib/studio/imageGen.ts:104](../../../lib/studio/imageGen.ts#L104)와 [lib/studio/detail/imageGen.ts:272](../../../lib/studio/detail/imageGen.ts#L272)의 `logger.info` 가 `durationMs`만 남긴다. UT 60건의 비용을 건별로 집계하려면 계기가 필요하다.

**해야 할 일 (작은 변경 2곳)**
1. `lib/studio/imageCost.ts` 신설 — §10-2 단가를 상수로 두고 `usage → USD` 를 계산하는 순수 함수. 단가는 env(`OPENAI_IMAGE_PRICE_*`)로 덮어쓸 수 있게 한다(요금 개정 대응). `usage` 가 없으면 `null` 을 돌려준다(추정치로 채우지 않는다). 계산식과 테스트 픽스처는 [scripts/ut/make-ut-products.mjs](../../../scripts/ut/make-ut-products.mjs)의 `costUsd()` 를 그대로 옮기면 된다.
2. 두 `logger.info` 에 `usage` 와 `usd` 를 추가하고, 잡이 자산 레코드에 합계를 남기게 한다.

**절차:** 파일럿 P01 1명(썸네일 1 + 상세 1) 실측 → 1024×1536 `edit` 단가 확정 → **20명 견적을 다시 계산해 승인받은 뒤** 배치를 시작한다.

| 상세페이지를 아키타입 대표 8명으로 축소 | 이미지 ~48콜 감소 (≈ $3.6) | 아키타입 C(콘텐츠 부재형) 4명은 반드시 유지 |

| 실패분만 재시도 | 중복 과금 방지 | 없음 — 기본 정책으로 채택 |

> **권장:** medium 유지. 총액이 1만~2만 원대라면 품질을 깎을 이유가 없다. 파일럿 실측이 이 판단의 근거다.
