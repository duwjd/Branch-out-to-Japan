## 핵심 차별점인 폐루프는 **화면에서 반증됐다**
"한 서비스로 이어져 보이는가" **Y 4 · N 16**. 순서 문제만이 아니다.
- **리포트가 스튜디오 산출물을 아예 보지 않는다**(UT-59) — 썸네일에 랭킹 배지가 붙어 있는데 "제3자 지표 ✕ 미관찰", 상세에 각주·정량이 있는데 "근거 라벨 0점". 게다가 **스튜디오가 만든 상세에 리포트가 「쓸 수 없다」고 판정한 표현(`鎮静`)이 그대로 살아 있는데 서비스가 못 잡는다**(P11).
- **제품 단위로 이어지지 않는다**(UT-58) — 상세 폼에 제품명 칸이 없어 생성기가 일본어 상품명을 스스로 짓는다. 같은 세션 안에서 리포트와 상세가 **서로 다른 제품**을 말한다.

## 아직 측정 못 한 것
- **이미지 API 실단가** — 단가 계산 모듈(`lib/studio/imageCost.ts`)은 만들었지만 **호출부와 DB 컬럼이 없어 원장이 한 건도 남지 않았다.** **추정치를 넣지 않는다.** 측정된 부수 지표는 상세 배경컷 **72장** 생성, 시간 예산 강등 **1컷**.
- **순서 효과** — 이번은 제작 → 진단 순서다. 진단을 먼저 본 사용자도 리포트를 고르는지는 모른다.
- **썸네일 styleId F**(모델컷 필요형) — 모델 자산이 없어 제출 버튼이 열리지 않았다.

## 실사용자 UT에서 확인할 것 셋
1. **"빠진 블록 N개" 화면을 보고 무엇을 하러 가는가** — 자료를 찾으러 가는가, 그냥 발행하는가. 이번엔 근거 보유량에 따라 신뢰(19/20)와 부담(7명 이탈 위기)으로 갈렸다.
2. **가격을 랜딩에 노출하면 신청률이 오르는가 내리는가** — 가격 부재를 14/20이 문제로 지목했는데(랜딩 마찰 8 + 마이페이지 이탈 6), 정작 30만원을 본 18명은 WTP 를 유지했다.
3. **안 읽히는 4블록(4·5·6·8)을 접으면 무엇이 달라지는가** — 스킵 사유가 예외 없이 "중복"이고, **블록5는 20명 중 읽은 사람이 0명**이다.
