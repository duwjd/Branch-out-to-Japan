# `docs/09-dev-spec.md` 반영 문안 (제안) — UT P0 대응

> ✅ **2026-08-21 반영 완료.** 아래 문안은 [[../../../09-dev-spec]] §4d · §1 · §5 · 변경 이력에 들어갔다. **이 파일은 그 제안본의 이력 보존용이며, 정본은 `docs/09-dev-spec.md` 다.**
> 반영 시 두 가지가 달라졌다 — ① M12-A 는 `c1f3d30` 으로 이미 해소돼 **완료(✅)로 기록**했고, ② 2차 세션에서 새로 잡힌 폐루프 P0(UT-58·59)가 **M12-B 로 신설**되어 나머지보다 앞선다.
> 근거: [UT-리포트.md](UT-리포트.md) · [이슈-백로그.md](이슈-백로그.md) · [P0-리포트-파이프라인-예산초과.md](P0-리포트-파이프라인-예산초과.md)

## 1. `§4d` 신설 — UT 대응 마일스톤 M12

`§4c 2차 개발 마일스톤` 다음에 절을 하나 추가한다. 기존 마일스톤 서술 방식(체크박스 + DoD)을 따랐다.

```markdown
## 4d. UT 대응 마일스톤 (2026-08-21 확정 — AI 에이전트 UT P0 해소)

> 근거 = `docs/research/ut-agent/results/UT-리포트.md` (합성 페르소나 20인 · 무효 0건).
> P0 11건을 세 묶음으로 나눈다. **M12-A 가 나머지 전부보다 먼저다** — ① 진단 리포트가 통째로 발행되지 않는 상태다.

### M12-A · 리포트 파이프라인 시간 예산 (최우선)
- [ ] `StructuredCallOptions` 에 `timeoutMs` 추가 → `lib/engine/llm/client.ts:149` 의 `messages.create(p)` 를 `messages.create(p, { timeout })` 로
- [ ] `lib/server/reportJob.ts` 에 `REPORT_BUDGET_MS = 270_000` — 상세 잡 `lib/studio/detail/budget.ts` 의 `JOB_BUDGET_MS` 와 같은 규칙
- [ ] 한국어 윤문 콜⑩ 진입 전 잔여 시간 검사 → 부족하면 건너뛰고 `humanizeSkipped: true` 기록
- **DoD:** 20계정 재실행에서 리포트 발행 성공률 **≥ 95%** · 콜별 소요가 잡 레코드에 남는다 · 예산 초과 시 `failed` 가 아니라 **윤문만 생략된 `published`** 로 끝난다
- **근거:** UT-T01 — 20/20 실패. 폐기 계정 3/3 재현. `POST` 11초 → `llmCalls` 22초 → `call4` 124초 → `humanize` 231초 → 300초 함수 상한 → 829초에 `failed` 확정

### M12-B · "말과 화면이 다르다" 6건 (문구·조건 분기 — 새 기능 없음)
- [ ] **UT-27** `/app/matching` 상단에 랜딩과 같은 고지를 둔다("MVP 검증 이후 제공을 검토하는 확장 서비스"). 버튼 "매칭 신청" → "사전 신청(MVP 이후 순차 안내)"
- [ ] **UT-25** `lib/studio/detail/templates.tsx:397` 의 아이브로우 폴백에서 한국어 `ctx.brandName` 을 제거 — 브랜드 킷 JA 표기 → 콜⑧ 번역 → 빈 값 순으로 폴백
- [ ] **UT-26** 상세 템플릿의 `signatureBlocks` 가 전부 근거 미충족이면 "추천" 배지를 붙이지 않고, 카드에 필요한 입력을 미리 표기
- [ ] **UT-28** 썸네일 템플릿 목록에서 **카피 슬롯 없는 문법(A·B)을 별도 그룹으로 분리** + 결과 화면에 "이 문법에서 우리가 한 일"(배경·조명·규정 판정)을 명시 + 근거 부족으로 A·B 밖에 못 고르는 사용자에게 "무엇을 채우면 카피형이 열리는가"를 그 자리에 표시
- [ ] **UT-08·09** 시즌 D-day 와 이벤트를 `brandProfile.category` · 채널 등록 여부 · 진출 단계로 분기
- **DoD:** 각 화면에서 랜딩 문구와 앱 문구가 같은 말을 한다 · 템플릿 이름과 산출물 내용이 일치한다
- **근거:** UT-27 은 **20/20 전원 지적 · 15/20 이탈 위기**로 이번 UT 최다. UT-28 은 A·B 배정 6명 **전원 차별성 2점**(카피형 14명은 4.00)

### M12-C · 지불 판단 정보 3건
- [ ] **UT-01** 랜딩·온보딩·진단 폼에 요금 표기 또는 "이 단계는 무료" 명시
- [ ] **UT-13** 사람 검수 유무를 플랜·결과 화면에 명시 — **없으면 없다고 쓰는 편이 낫다**
- [ ] **UT-19** 스튜디오 예시 이미지에 "이 서비스가 만든 결과" / "일본 시장 참고 사례" 구분 표기
- [ ] **UT-44** FREE 플랜 설명을 실제 무료 범위와 일치시킨다 — 지금은 "약기법 간이 체커만"이라 써두고 썸네일·상세를 무료로 내준다
- **DoD:** 로그인 전에 가격 감이 잡힌다 · 유료 상품에 포함이라 적힌 것을 무료로 내주지 않는다
- **근거:** WTP 17/20 인데 **NPS −70 · 9점 이상 0명**. 사겠다는 사람은 많은데 확신을 못 준다
```

## 2. `§1 스택·환경` — 이미지 비용 계기 (미배포 상태 명시)

§1 표 아래 잠정 사항에 한 줄 추가한다. **`.env` 편집이 이 머신에서 차단되어 있어 키 반영은 사용자가 해야 한다.**

```markdown
**이미지 비용 계기(2026-08-21 구현 · 미배포):** `lib/studio/imageCost.ts` 가 OpenAI 응답 `usage` 로 콜별 USD 를 계산하고, `generated_assets.image_usage jsonb` 에 원장을 남긴다. `usage` 가 없으면 `null` 을 반환하며 **추정하지 않는다**. 단가 override 는 `OPENAI_IMAGE_PRICE_IMAGE_INPUT` · `_CACHED_INPUT` · `_TEXT_INPUT` · `_OUTPUT`(1M 토큰당 USD, 각각 기본 8 / 2 / 5 / 30).
**적용 잔여:** `npm run db:push` → 배포. **미적용 상태라 UT 에서 비용을 실측하지 못했다**(UT-리포트 §11).
```
