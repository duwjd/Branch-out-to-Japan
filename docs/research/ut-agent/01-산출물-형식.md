# AI 에이전트 UT — 산출물 형식

> 계획: [00-ut-plan](00-ut-plan.md) · 실행 프롬프트: [02-실행-프롬프트](02-실행-프롬프트.md)
> 산출물은 **5종 + 발표용 1장**. 원시 로그(증거) → 기계 집계(수치) → 종합 리포트(해석) → 백로그(행동) 순으로 층이 올라간다. 아래 층은 위 층을 **인용**해야 하며, 인용 없는 주장은 리포트에 넣지 않는다.

| # | 산출물 | 경로 | 커밋 |
|---|---|---|---|
| 1 | 캡처 원본·매니페스트 | `.ut/runs/{PID}/` | ✕ (로컬) |
| 2 | 페르소나 원시 응답 | `.ut/runs/{PID}/response.md` → 취합본 `results/원시응답.md` | ○ 취합본만 |
| 3 | 점수 집계 | `results/scores-task.csv` · `results/scores-persona.csv` · `results/랜딩평가.csv` · `results/생성결과.csv` · `results/비용측정.csv` | ○ |
| 4 | 종합 UT 리포트 | `results/UT-리포트.md` | ○ |
| 5 | 이슈 백로그 | `results/이슈-백로그.md` | ○ |
| 6 | 발표용 1장 요약 | `results/한장요약.md` | ○ |

(`results/` = `docs/research/ut-agent/results/`)

## 1. 캡처 매니페스트 — `manifest.json`

드라이버가 쓴다. **페르소나 체감이 아니라 기계 실측**이라, "느리다고 했는데 실제로 얼마였나"를 대조하는 근거가 된다.

```json
{
  "personaId": "P01",
  "account": "test01@example.com",
  "brand": "글로우리프",
  "track": "A",
  "env": { "baseUrl": "https://branch-out-to-japan.vercel.app", "llmMode": "real", "imageMode": "real", "imageModel": "gpt-image-2", "imageQuality": "medium", "store": "supabase" },
  "startedAt": "2026-08-20T10:00:00+09:00",
  "steps": [
    {
      "seq": 1, "id": "landing", "task": "T0", "label": "랜딩 첫 화면(비로그인)",
      "url": "/", "action": "goto",
      "png": "screens/01-landing.png", "txt": "screens/01-landing.txt",
      "elapsedMs": 1840, "consoleErrors": [], "failedRequests": []
    },
    {
      "seq": 12, "id": "detail-processing", "task": "T5", "label": "상세페이지 생성 대기",
      "url": "/app/studio/detail/xyz789", "action": "poll",
      "png": "screens/12-detail-processing.png",
      "elapsedMs": 147300,
      "progress": ["블록 2/9", "블록 5/9", "블록 9/9"],
      "consoleErrors": [], "failedRequests": []
    }
  ],
  "generations": {
    "report":    { "status": "published", "id": "abc123", "mode": "brandProduct", "elapsedMs": 143000, "artifact": "artifacts/report.html" },
    "thumbnail": { "status": "done",      "id": "thm456", "styleId": "C", "proofBadge": false, "elapsedMs": 78200, "artifact": "artifacts/thumbnail.png",
                   "images": [ { "call": "edit", "size": "1024x1024", "usage": { "input_tokens": 1180, "text_tokens": 320, "image_tokens": 860, "output_tokens": 1056 }, "usd": 0.0418 } ] },
    "detail":    { "status": "done",      "id": "xyz789", "templateId": "D2", "blocks": 15, "aiCuts": 6, "degradedCuts": 0, "skippedBlocks": ["proof"], "elapsedMs": 168400, "artifact": "artifacts/detail-master.jpg",
                   "images": [ { "call": "edit", "size": "1024x1536", "usage": { "input_tokens": 1240, "output_tokens": 1584 }, "usd": 0.0574 } ] }
  },
  "imageCost": { "calls": 7, "usd": 0.402 },
  "outcome": { "T0": "완료", "T1": "완료", "T2": "완료", "T3": "완료", "T4": "완료", "T5": "부분완료", "T6": "완료", "T7": "완료" },
  "totalElapsedMs": 612000
}
```

> `generations` 3항목은 **UT 결과와 별개로 그 자체가 제품 안정성 데이터**다. 60건 중 몇 건이 실패했는지가 배포 판단 근거가 된다.
> `images[].usage` · `imageCost` 는 **비용 실측**이다. 계기는 `lib/studio/imageCost.ts`(신설)가 붙이고, 없으면 `usd` 는 null 로 둔다 — 추정치를 실측 자리에 넣지 않는다.
> `degradedCuts` 는 [budget.ts](../../../lib/studio/detail/budget.ts) 가 시간이 모자라 텍스트로 강등한 컷 수다. **0이 아니면 그 건의 산출물 평가에 주석을 단다** — 품질 저하가 서비스 탓이 아니라 실행 조건 탓일 수 있다.

## 2. 페르소나 원시 응답 — `response.md`

**페르소나 목소리 그대로.** 보고서 말투로 정리하지 않는다. 카피·UI 문구를 고칠 때 쓰는 원자재다.

````markdown
# P01 — 글로우리프·김서연 (7인 세라마이드 크림, Qoo10 입점준비, AI 반신반의)

> 트랙 A · test01@example.com · branch-out-to-japan.vercel.app · 2026-08-20 · LLM/이미지 실모드 · 총 11분 20초

## T0 랜딩페이지 (로그인 전) — 매력도 3/5 · 흥미도 4/5
① **3초 첫인상:** (…히어로만 보고…)
② **이게 뭐 해주는 서비스인가 (내 말로):** (…)
③ **내 상황과 맞나:** (…)
④ **로그인/신청까지 갈 마음:** 3/5 — (이유)
⑤ **이탈 포인트:** "○○" 섹션에서 닫았을 것 같다
- **끝까지 스크롤했나:** 아니오 — 8번째 섹션에서 멈춤
- **가장 눈에 걸린 문장:** "번역이 아니라 진단이 먼저" (원문 인용)
- **가장 걸리적거린 문장:** "(원문 인용)" — 이유

## T1 로그인과 첫 진입 — 완료 · 만족도 3/5
(…페르소나 구어체…)
- **눈에 걸린 것:** (…)
- **그냥 지나친 것:** (…)
- **이탈할 뻔한 지점:** 없음

## T2 브랜드 등록 — 완료 · 만족도 3/5
- **막힌 곳:** 포지셔닝 태그 16개 중 뭘 골라야 할지 30초쯤 헤맴
- **과하다고 느낀 입력:** 브랜드 킷

## T3 진단 리포트 — 완료 · 만족도 4/5
- **대기 중 생각:** "2분이면 기다릴 만은 한데 뭘 하고 있는지는 모르겠어요"
- **실제로 읽은 블록:** 0(표지)·2·4·9 / **건너뛴 블록:** 6·7

## T4 썸네일 — 부분완료 · 만족도 2/5
- **템플릿 고른 이유:** (…)
- **가격 자리가 비어 있는 것에 대해:** (…)
- **리포트가 반영됐다고 느꼈나:** 아니오 — "따로 노는 것 같아요"

## T5 상세페이지 — 완료 · 만족도 4/5
- **표시 의무 3항(내용량·구분·판매원)을 요구받았을 때:** (…귀찮음 / 신뢰 중 어느 쪽인지…)
- **2분 반 대기:** (…)
- **빠진 블록 안내를 어떻게 읽었나:** (…)

## T6 운영 3화면 — 완료 · 만족도 3/5
- **방금 만든 자산 3건이 제대로 보였나:** (…)
- **기업 매칭 이해:** "지금 되는 서비스인 줄 알았어요" ← 오해 발생

## T7 종합
- **이 서비스를 한 문장으로:** "(페르소나가 직접 말한 정의)"

## 산출물 평가
| 산출물 | 정확성 | 실행가능성 | 차별성 | 신뢰성 | 그대로 쓸 것인가 |
|---|---|---|---|---|---|
| 진단 리포트 | 4 | 3 | 4 | 2 | 손보면 Y |
| 썸네일 | 2 | 2 | 2 | 3 | N |
| 상세페이지 | 4 | 4 | 4 | 3 | 손보면 Y |

**근거 인용 (산출물별 1개 이상 필수)**
- 리포트: "블록 4의 NG 표현 3개가 우리가 실제로 쓰던 문장이었어요"
- 썸네일: (…)
- 상세페이지: (…)

**틀렸다고 생각한 대목:** (직접 인용 + 왜 틀렸는지)

## 지불 의향
- **낼 것인가:** 예 — **금액:** 30만 원 (내 상한 50만 원 안)
- **가장 돈값 하는 산출물:** 상세페이지
- **이유:** (…)
- **NPS:** 7 / 10 · **재방문:** 예

## 마지막 3문장
- 가장 좋았던 것: (…)
- 가장 나빴던 것: (…)
- 없어서 못 사는 것: (…)
````

**작성 규칙**
- 화면에 없는 내용을 근거로 들면 그 문항은 `[환각]`으로 표시하고 점수에서 제외한다.
- 점수에는 **반드시 화면 인용**이 붙는다. 인용 없는 점수는 무효.
- 페르소나 데이터(가격 상한·AI 수용도·결재 권한)와 어긋나는 결론은 무효 — 재실행한다.
- 제품컷이 무지 용기라 "내 제품 같지 않다"는 반응이 나오면 `[자극물 한계]`로 표시하고 정확성 점수에서 제외한다.

## 3. 점수 집계

세 파일로 나눈다. 축이 다른 데이터를 한 시트에 섞지 않는다.

**`scores-task.csv`** (20명 × 8과업 = 160행)
```csv
persona_id,archetype,lens,track,task_id,outcome,satisfaction,dropoff_step,elapsed_sec,blocker
P01,A,-,A,T0,완료,3,,88,8번째섹션이탈
P01,A,-,A,T1,완료,3,,42,
P01,A,-,A,T2,완료,3,,96,포지셔닝태그선택혼란
P01,A,-,A,T5,완료,4,,151,
P05,A,ai_resist,A,T3,부분완료,2,report-processing,198,AI표기거부
```
- `lens`: `ai_resist` / `approval` / `no_jp` / `-` (복수는 `;`)
- `outcome`: `완료` / `부분완료` / `실패`
- `dropoff_step`: manifest `steps[].id`. 이탈 없으면 빈칸

**`scores-persona.csv`** (20행)
```csv
persona_id,archetype,lens,rep_acc,rep_act,rep_dif,rep_tru,thu_acc,thu_act,thu_dif,thu_tru,det_acc,det_act,det_dif,det_tru,best_asset,wtp,wtp_krw,nps,revisit,invalid_flags
P01,A,-,4,3,4,2,2,2,2,3,4,4,4,3,detail,Y,300000,7,Y,
P19,D,ai_resist,2,2,3,2,1,2,2,2,2,2,2,2,report,N,0,3,N,
```
- `rep_*`=리포트 · `thu_*`=썸네일 · `det_*`=상세페이지 / `acc`정확성 `act`실행가능성 `dif`차별성 `tru`신뢰성
- `best_asset`: `report` / `thumbnail` / `detail` / `none`
- `invalid_flags`: `price_overrun` / `ai_no_resist` / `approval_bypass` / `hallucination` / `positivity` — 있으면 그 행은 **집계에서 제외**하고 리포트 §한계에 건수를 적는다

**`랜딩평가.csv`** (20행 — T0 전용. 2026-07 랜딩 시안 시뮬과 같은 척도라 직접 비교한다)
```csv

```
- `appeal` 매력도 / `interest` 흥미도 / `intent` 다음 행동 의향 — 전부 1~5
- `intent` 는 2026-07 시뮬의 "가입 의향 N/5"와 같은 척도다. 시안 평균과 나란히 놓는다

## 5. 산출물 평가
### 5-1. 진단 리포트 (20건)
- 4축 평균·분포 + **가장 낮은 축의 원인 분석**

- 템플릿 A~H별 만족도 — **어느 템플릿이 죽었는가**

- **표시 의무 3항 요구**가 신뢰로 읽혔는가 마찰로 읽혔는가
- 130~155초 대기 이탈자 수
### 5-4. 3종 비교
"가장 돈값 하는 산출물" 투표 결과 ← **어느 축에 가격을 붙일지의 근거**

## 5. 이슈 백로그 — `이슈-백로그.md`

**바로 티켓이 되는 형태.** 관찰이 아니라 행동으로 끝나야 한다.

```markdown
| ID | 심각도 | 화면 | 증상 | 영향 인원 | 근거 | 수정 제안 | 담당 |
|---|---|---|---|---|---|---|---|
| UT-01 | P0 | /app/matching | 확장 가설인 기업 매칭을 현재 제공 기능으로 오해 | 11/20 | P01·P08·P14 인용 | 화면 상단에 제공 시점 명시 · 신청 버튼 문구 변경 | pm |
| UT-02 | P0 | /app/studio/thumbnail | 진단 리포트 결과가 썸네일에 반영됐다는 신호가 없어 별개 도구로 인식 | 14/20 | P01·P11·P16 인용 | 생성 폼·결과에 "이 리포트 기준" 표기 | frontend |
| UT-03 | P1 | /app/brand | 포지셔닝 태그 16종 선택 기준 불명 | 9/20 | — | 태그 그룹핑 또는 카테고리별 기본 추천 | designer |
```

**심각도 기준**
| 등급 | 정의 |
|---|---|
| **P0** | 과업 실패를 만들거나, **포지셔닝을 훼손**하거나(금지 포지션 오해·미구현 기능 오인), 지불 의향을 꺾거나, **생성 실패율 10% 초과**를 유발한다 |
| **P1** | 과업은 되지만 마찰이 크다. 3명 이상 |
| **P2** | 개선하면 좋다. 1~2명 |

> 규칙: 이슈 1건 = 화면 1개 + 증상 1개. "전반적으로 어렵다"는 이슈가 아니다. 쪼개거나 버린다.
