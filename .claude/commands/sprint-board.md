## 문서 ↔ 이슈 대조

!`node scripts/sprint/doc-sync.mjs`

## 할 일

위 출력만으로 답한다. 티켓 파일이나 문서를 다시 읽지 않는다.

1. 한 줄 요약 — 스프린트 목표와 진행률
2. **진행·차단을 먼저**, 대기는 그다음. 완료는 세기만 한다
3. 주의가 필요한 것만 짚는다:
   - 어긋난 행이 있으면 **어느 쪽이 맞는지** 묻는다. 이슈가 정본이지만, 문서만 🔵 인 경우는 대개 라벨을 안 붙인 것이다
   - 문서 §작업 보드에 없는 열린 이슈 → 지도에서 빠진 일감이다
   - 사용자 작업(U1~U7)이 막고 있는 마일스톤
4. "다음에 뭘 할까"를 물었다면 하나만 추천하고 이유를 한 줄로 댄다

## 하지 말 것

- 이슈 상태를 바꾸지 않는다. 이 명령은 읽기 전용이다
- 모든 이슈를 다시 나열하지 않는다. 사용자는 위 출력을 이미 봤다
- 보드에 없는 내용을 추측해서 채우지 않는다

## `/status` 와의 차이

`/status` 는 `docs/04-roadmap.md` 기준으로 **Phase 대비 진척**을 본다.
이 명령은 **이번 2주의 일감**을 본다. 둘은 층위가 다르다.

## 캐시 주의

`.sprint/cache/` 는 GitHub 이슈의 캐시다. 오래됐다고 판단되면 `/sprint-sync` 를 먼저
쓰라고 안내한다. 여기서 직접 동기화하지 않는다.
