# YOAKE 랜딩 히어로 영상

랜딩페이지 맨 위에 넣는 제품 소개 영상이다. **16:9 · 1920×1080 · 25초 · 30fps · 무음(오디오 트랙 없음) · 루프.**
[HyperFrames](https://hyperframes.heygen.com)(HTML + GSAP 타임라인을 프레임 단위로 렌더)로 만들었다.

| 파일 | 용도 |

## 구성 근거 — 레퍼런스 리서치 (2026-11-24)

두 번 조사했다. ① 제품 영상을 히어로에 쓰는 SaaS 랜딩의 영상 파일을 재고(ffprobe) 페이지 마크업을 읽었다.
② 공식 채널의 제품 영상 8편(Notion Mail · Linear Releases · Linear Agent · Framer 2편 · Vercel v0 · Ramp · Arc 1.0)을
프레임 시트로 실측하고, 모션 가이드(GSAP SplitText · Material 3 · IBM Carbon · Netflix 한국어 자막 기준)를 읽었다.

### ① 영상 구조

| 본 것 | 관찰 | 이 영상에 반영한 것 |
|---|---|---|
| 길이 | 히어로 루프는 11~25초 — Notion 11초 · Ramp 13초 · Airtable 16.4초 · Dia 19초 · Framer 21초 · Descript 25.5초 | 25초(요청) — 관찰 범위의 위쪽 끝 |
| 서사 | **입력 → 상태 문구 → 결과물 → 처음으로**. 기능을 나열하지 않고 한 번의 사용 흐름을 보여 준다 | 카피 입력 → "진단하는 중" → 리포트 → 이미지·템플릿 → "만드는 중" → 결과물 |
| 카메라 | 한 요소를 크게 → 맥락 → 다시 한 요소. 전체 화면을 그대로 보여 주면 글자가 안 읽힌다 | 장면마다 1.5~3.0배로 확대. 앱 사이드바를 빼고, 위아래 가장자리에서 글줄이 잘리지 않게 구도를 잡았다 |
| 강조 | 보는 곳만 남기고 나머지는 어둡게·흐리게. 커서는 누르는 순간에만 크게 | 실제 화면에서 오려 낸 조각을 띄우고 나머지에 막을 깐다. 커서는 클릭 세 번에만 나온다 |
| 틀 | 브라우저 창 틀은 드물고, 단색 브랜드 배경 위에 UI를 카드로 띄운다 | 크림 배경 + 둥근 카드 |
| 용량 | 잘 만든 히어로는 1.9~2.5MB | 2.3~2.4MB |

### ② 타이포그래피 모션

| 본 것 | 관찰 | 이 영상에 반영한 것 |
|---|---|---|
| 글자의 자리 | **UI 위에 붙박인 자막·로어서드는 8편 중 0편.** 글자는 전면 중앙 타이틀 카드이거나 확대된 UI 자체의 글자다(Notion은 카드 7장이 UI 줌과 교대) | 아래 띠 자막과 단계 눈금을 없앴다. 큰 제목 3장이 화면 장면과 번갈아 나온다 |
| 글자와 화면 | 한 번에 하나만 주도한다 — 줌이 끝나고, UI가 멈춘 뒤, 글자가 나온다 | 제목이 나올 때 스테이지는 물러나 있고, 제목이 다 빠진 뒤 스테이지가 들어온다 |
| 들어오는 법 | 어절 단위 마스크 슬라이드업이 표준 — 0.6초 · 간격 60ms · `expo.out`(GSAP SplitText 데모 · Osmo 프리셋) | 어절이 마스크 아래에서 0.6초 · 60ms 간격 · `expo.out` 으로 올라온다 |
| 나가는 법 | 가속 커브로 짧게, 들어올 때보다 덜 움직인다. 튕기는 오버슈트는 피한다(M3 · Carbon) | 0.16초, 위로 40%만 뜨며 사라진다. `back`·`bounce` 이징은 쓰지 않는다 |
| 읽을 시간 | 다 뜬 뒤부터 빠지기 시작할 때까지를 잰다. 한국어 자막 상한은 12자/초 · 줄당 16자 · 2줄(Netflix). 실측 카드는 3~4단어를 약 2초 노출 | 한 줄 12자 안쪽 · 2줄까지 · 줄바꿈은 손으로. 정착 후 1.0~1.2초 머문다(12자/초 하한은 넘고, 권장 8자/초에는 조금 못 미친다) |
| 쪼개는 단위 | 헤드라인은 글자가 아니라 단어·줄 단위가 읽기 쉽다. 한글은 어절이 마스크 단위로 알맞다 | 어절 단위. 받침과 밑줄이 잘리지 않게 마스크 상자에 위아래 여유를 뒀다 |
| 강조 장치 | 영상마다 **한 가지만** 반복한다(Linear는 타자기, Notion은 정지 글자 + 비행기). 효과를 쌓는 것이 흔한 실수 | 밑줄 하나 — 어절이 자리 잡은 뒤 한 번 긋는다. 예외는 "한국어 카피를 → 일본어 문구로" 단어 굴림 한 번(Ramp · v0 의 단어 교체와 같은 계열) |
| 덧붙인 꼬리표 | UI 중심 영상 5편은 0개 — 줌으로 UI 자체의 라벨을 키우고 커서로 가리킨다 | 화면 장면에는 글자를 덧붙이지 않는다. 결과물 이름표 둘("썸네일" · "상세페이지")만 남겼다 |
| 로고 엔드카드 | 가운데 로고를 2.5~4.5초 유지. 심볼이 먼저, 워드마크가 뒤따른다. 태그라인은 드물다 | 해가 수평선 위로 오르고 → 선 → 글자 → 한 줄. 약 2.7초(다음 회차 첫 0.3초로 이어진다) |

조사한 영상은 공식 유튜브 업로드본이고 시간 오차는 ±0.1~1초다. Apple · Stripe · Figma 등은 측정하지 못했다.
HyperFrames 카탈로그의 `text-stagger` · `inline-highlight` · `text-state-swap` 컴포넌트가 같은 수치(0.54초 · 90ms 간격, 밑줄은 `scaleX`)를 쓴다.

## 규정을 말하는 두 대목 — 근거와 문구의 선

제목 2·3 은 제품이 실제로 하는 일을 말한다. 화면에서 강조하는 것은 전부 실제 UI 요소다.

| 영상의 말 | 제품 안의 근거 | 화면에서 보이는 것 |
|---|---|---|
| 일본 광고 규정 기준으로 일본어 문구로 재설계 | 진단 엔진의 문장 단위 薬機法 스크리닝과 재작성(`lib/engine/rules/`), 리포트의 "약기법 1차 스크리닝" 표시 | 재작성 카드의 "푸는 문제 · … (薬機法 불가)" → "+ ※角層 조건 각주" 칩 |
| 쇼핑몰 썸네일 규정에 맞춘 템플릿 | 템플릿 프롬프트 팩의 몰별 제약 — 아마존JP 메인 이미지(순백 배경 · 오버레이 없음), 라쿠텐 가이드라인(테두리 금지 · 텍스트 점유 20% 이하), 몰별 추천 템플릿(`data/processed/thumbnail-style-prompts.json` · `docs/research/jp-thumbnail-style-taxonomy.md`) | 몰 필터 칩, 템플릿 카드의 추천 · △ 부적합 표시, 결과 화면의 "라쿠텐 공식샵 기준" |

**문구는 "기준으로 · 맞춘"까지만 쓴다. "규정을 지킨 · 준수 · 통과"라고 쓰지 않는다.**

- 랜딩의 필수 고지가 "YOAKE는 법적 적합성이나 심의 통과를 보증하지 않습니다"이고, FAQ 도 "공개된 규정을 기준으로 한 1차 스크리닝"이라고 답한다(`app/landing/content.ts`).
  리포트 자체도 "법적 확정 판정이 아닙니다"라고 적는다(`lib/engine/rules/assemble.ts`).
- 썸네일의 몰 규정은 프롬프트 제약과 템플릿 설계에 들어 있을 뿐, 생성된 이미지를 자동으로 검사하지는 않는다
  (검수 게이트 v1 은 라벨 보존 · 오탈자 · 무단 배지의 구조적 보증 기록이다 — `lib/server/studioJob.ts`).
- 그래서 규정을 말하는 제목 2 가 자리 잡는 순간부터 재설계 장면이 끝날 때까지 고지 한 줄을 함께 띄운다.

## 어떻게 만들어졌나

- **화면은 실제 앱 캡처다.** `capture/capture.mjs` 가 로컬 dev 서버의 실제 화면을 뷰포트 1440×900 · 3배율(4320×2700)로 찍고,
  확대·강조할 요소의 좌표를 `assets/ui/rects.json` 에 남긴다. 영상은 이 캡처를 카메라(`#cam`)로 확대할 뿐 UI를 다시 그리지 않는다.
- **캡처 위에 덧그린 것:** 점수 링의 카운트업, 카피가 채워지는 순간, 드롭존에 놓이는 이미지, 원본→결과로 닦아 내는 막,
  커서, 상태 문구("진단하는 중" · "만드는 중"). 그 밖의 강조(떠오르는 조각·어두운 막·흐린 배경)는 같은 캡처를 오려 쓴 것이다.
  상태 문구는 실제 대기 화면이 아니라 "누른 뒤 결과가 나오기 전"을 나타내는 한 박자짜리 표식이다(실제 생성에는 훨씬 오래 걸린다).
- **결과물 장면의 썸네일·상세페이지 카드**는 화면 캡처가 아니라 결과 이미지 파일을 카드로 세운 것이다(`assets/out/`).
  썸네일은 결과 화면 속 이미지 자리에서 그대로 떠오른다.
- **로고는 자산 그대로다.** `design/brand/logo/yoake-logo.svg` 의 도형·비율·색을 인라인으로 옮겨 조각별로 등장만 시킨다
  (해는 수평선 클립 뒤에서 올라온다 — 다 오른 모양이 자산의 69% 노출과 같다). 그림자·광택·재조판은 없다.
- **캡처할 때 감춘 것:** dev 전용 표식(로컬 저장·목 모드 배지, "데모 이미지입니다" 배너). 운영 화면에는 없는 것들이다.
- **화면의 내용은 예시 데이터다.** 키 없는 로컬 목 모드에서 찍었고, 리포트 수치·문구는 팀 골든 샘플
  `docs/specs/01-report-sample-cica-ampoule.md`(가상 브랜드 HARUON)에서 옮겼다 — `capture/stage-demo-data.py`.
  결과물 장면 아래에 "화면과 결과물은 예시입니다"가 함께 나간다.
- **예시 썸네일의 목표 몰은 라쿠텐 공식샵으로 맞췄다.** 고른 템플릿(공식샵 신뢰 배지형 = 라쿠텐 공식샵 문법)과 결과 화면의
  "○○ 기준" 문구가 같은 몰을 가리키게 하려는 것이다(`capture/stage-demo-data.py`). 캡처도 몰 필터에서 라쿠텐 공식샵을 고른 상태로 찍는다.
- **글자는 진단 결과가 제작의 입력으로 들어간다고 말하지 않는다.** 현재 스튜디오는 리포트를 읽지 않는다(폐루프 미연결).
  영상 속 리포트 제품(CICA 앰플)과 썸네일 제품(톤업 선케어)도 서로 다르다 — 같은 브랜드의 두 제품으로 읽힌다.

## 다시 만들기

```bash
# 1) 예시 데이터 → 2) 실화면 캡처 (저장소 루트에서, dev 서버가 떠 있어야 한다)

YOAKE_SESSION=<yoake_session 쿠키 값> YOAKE_REPORT_ID=<진단 요청 id> YOAKE_THUMB_ID=<썸네일 자산 id> \
  node video/landing-hero/capture/capture.mjs

# 3) 점검 → 프레임 확인 → 렌더 (video/landing-hero 에서)
npm run check
npx hyperframes@0.9.87 snapshot --at 0,1.6,4.2,7.0,9.6,11.6,12.9,15.2,17.6,18.3,21.9,24.9 --no-end
npx hyperframes@0.9.87 render -q delivery -f 30 --format mp4 -o renders/yoake-landing-hero-master.mp4

# 4) 웹용 인코딩 — 오디오 트랙을 넣지 않는다(-an)
M=renders/yoake-landing-hero-master.mp4
ffmpeg -y -i $M -an -c:v libx264 -preset veryslow -crf 27 -pix_fmt yuv420p -movflags +faststart -g 60 out/yoake-landing-hero.mp4
ffmpeg -y -i $M -an -c:v libvpx-vp9 -crf 40 -b:v 0 -row-mt 1 -cpu-used 1 -pix_fmt yuv420p -g 60 out/yoake-landing-hero.webm

# 5) 포스터(0프레임) → 랜딩이 쓰는 자리로 복사
ffmpeg -y -i $M -vf "select=eq(n\,0)" -frames:v 1 out/poster.png   # → webp 로 바꿔 out/yoake-landing-hero-poster.webp
cp out/yoake-landing-hero.webm out/yoake-landing-hero.mp4 out/yoake-landing-hero-poster.webp ../../public/video/
```

- 캡처 화면의 레이아웃이 바뀌면 `rects.json` 의 좌표를 `index.html` 스크립트 맨 위 `R` 과 카메라 구도 `SHOTS` 에 옮겨 적는다.
- 제목 어절의 처음 위치는 CSS 가 아니라 `gsap.set` 으로 정한다 — CSS `translateY(%)` 로 두면 GSAP 이 px 로 읽어 들여 어절이 마스크 밖에 남는다.
- `npm run check` 에 남는 경고는 알고 둔 것이다 — `composition_file_too_large`, `film_silent`(무음은 요청 사항).
- HyperFrames 스킬(`/hyperframes` 등)은 설치돼 있지 않다. 쓰려면 `npx hyperframes skills update` 를 직접 실행한다.

## 랜딩에 들어간 모습 (2026-11-24)

랜딩(`/`) 첫 화면이 이 영상이다 — `components/landing/HeroVideoStage.tsx` · 문구와 경로는 `app/landing/content.ts` 의 `HERO_VIDEO`.

- **테두리 없이 얹는다.** 영상 바탕(`#faf8f5`)이 페이지 바탕과 같아, 큰 제목이 페이지의 헤드라인처럼 보인다.
  그래서 영상 속 배경 글로우는 **프레임 안에서 0 으로 잦아들게** 그렸다(가장자리에서 잘리면 페이지 위에서 얼룩이 된다).
  인코딩으로 바탕색이 1단계쯤 어긋나는 것은 가장자리 3~4% 를 풀어 주는 마스크가 가린다(`app/globals.css` `.lp-hero-video`).
- **스크롤 전환.** 넓은 화면에서는 영상이 헤더 아래에 고정되고, 기존 Hero(헤드라인·CTA·목업)가 윗변이 번진 채 그 위로 올라온다.
  덮이는 만큼 영상이 줄고(−7%), 흐려지고(투명도 제곱), 초점이 풀린다(블러 10px). 다 가려지면 재생을 멈췄다가 돌아오면 다시 튼다.
- **재생 규칙.** `autoplay` 속성을 쓰지 않고 스크립트로 튼다 — 모션 최소화나 데이터 절약이 켜져 있으면 틀지 않고 포스터만 보여 준다.
  멈춤·재생 버튼이 영상 왼쪽 아래에 있다(WCAG 2.2.2). 사용자가 멈추면 스크롤로 돌아와도 다시 틀지 않는다.
- **좁은 화면·모션 최소화**에서는 고정과 변형 없이 영상 → Hero 가 위아래로 이어진다.
- 모바일에서는 16:9 가 작아 UI 장면의 글자를 읽기 어렵다. 조사한 사이트 여럿이 1:1 컷을 따로 냈다 — 필요하면 같은 컴포지션에서 구도만 바꿔 뽑는다.
